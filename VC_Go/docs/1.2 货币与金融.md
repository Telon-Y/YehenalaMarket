## M4（迁自 1.0 §4.5.1a + 1.2 §3.6/§3.7）：**金融商品与所有权重构**（2026-09-20 裁决）

> **状态**：**已裁决方向，待实现**。本条把 1.2 草案 §3.6"金融商品"与 §3.7"金融区"
> 与 1.0 的**私有化收购**接成一条链——**金融商品是私有化收购的进阶版本**。

### M4.1 金融商品 = 私有化收购的进阶版本

1.0 的私有化（§4.5.1a）是"**政府级 → 私有级**"的一次性收购订单（对价 = 建造成本 × 建造力价）。
1.2 把它**进阶**为**可交易的金融商品**：

| 维度 | 1.0 私有化收购 | 1.2 金融商品 |
|------|---------------|-------------|
| 标的 | 一次转让若干**级**的所有权 | **每级发行一份收益权商品**（1 级 = 1 份） |
| 交易方向 | 单向：政府 → 私有 | **单向，只能从左往右**（详下） |
| 出资方 | 政府 ↔ 私有级之间的一次性收购 | **储蓄银行**（买金融区发行的"债券"，见 M4.3） |
| 定价 | 建造成本 × 建造力价 × 倍数 | **随建造力波动的价格**（不自主波动） |
| 收益 | 按持股分红（§4.5.1） | 持有者获**每周期对应分红** |

**交易规则（2026-09-20 第 2 次裁决，纠正"顺序交易"的措辞）**：

> "交易**不是顺序交易**，而是**单向交易**，**只能从左往右**，**不能同级交易**，
> 也**不能从右往左**。"

即链条 **政府 → 劳动力 → 金融区** 是**资金/股权的流向**，不是"必须按次序发生的一串交易"：

| 允许 | 禁止 |
|------|------|
| 政府 → 劳动力 | 劳动力 → 政府（从右往左） |
| 劳动力 → 金融区 | 金融区 → 劳动力（从右往左） |
| **相邻两级之间**的交易 | **同级之间**（政府↔政府、劳动力↔劳动力、金融区↔金融区） |
| | 跨级直连（政府 → 金融区） |

> **歧义标注（Ⅰ）→ 已澄清（2026-09-20 第 3 次裁决）**：
> "不能同级交易"= **A 所有的东西不能被 A 自己私有化**——
> 具体地："**劳工不能私有化劳工所有的建筑**"。即**所有权主体不能从自己手里买**，
> 这与"逐级可拆分性"无关。

### M4.2 所有权重构

**裁决原文**："完成后将 **30% 的政府所有改为资本所有**，**70% 资本所有改为劳动力所有**。"

**1.0 现状（实测，tick 1）**：

| 类别 | 政府级 | 私有级 | 说明 |
|------|-------:|-------:|------|
| 生产建筑（可私有化者） | **30%** | 70% | 每股 1.5 / 3.5 级；`s_gov = 0.30` |
| **金融区**（工业资本的载体） | 0 | **100%** | 它就是"私有级"的持有者（§4.5.2） |
| **宅邸庄园**（农业资本的载体） | 0 | **100%** | 同上（§4.5.5，农业建筑） |

**按字面执行的算术**：

$$30\%\ \text{政府} \to \text{资本所有};\qquad 70\%\ \text{资本所有} \to \text{劳动力所有}$$

**过渡后的持股：资本 30% + 劳动力 70%。**

**农业的口径（2026-09-20 第 2 次裁决）**：

> "**农业中自给农场不变**，**商品农场所有权改变**。"

| 农业部门 | 是否参与所有权重构 |
|----------|------------------|
| **自给农场**（每级未使用耕地自动生成，§4.2） | **不变**——它本就不是商品生产建筑，其所有权载体是**宅邸庄园**（§4.5.5），本次不改 |
| **谷物农场 / 棉花种植园**（商品农场） | **所有权改变**——与工业建筑同办（30% 政府→资本、70% 资本→劳动力） |

> 这一条**消解了上一轮的待澄清点①**（"庄园/农业建筑是否同办"）：答案是
> **商品农场同办、自给农场不同办**。宅邸庄园作为**自给农场**的所有权载体不变，
> 它作为**商品农场**的资本载体那部分则转出给劳动力。

**劳动力持有的口径（2026-09-20 第 2 次裁决）**：

> "劳动力**不分阶级**，视作**一同管理**，按**劳动力数量比例平分**分红。"

| 项 | 口径 |
|----|------|
| 持有主体 | **一个**主体（"劳动力"），**不按阶级拆分** |
| 分红分配 | 按**劳动力数量比例**平分 |
| 对 1.0 的影响 | 需要一个**新的账本主体**（劳动力池），与 §5.1 的"场地 × 阶级"39 个池**并存或改造**——待 1.0 化时定 |

> **歧义标注（Ⅱ）→ 已澄清（2026-09-20 第 3 次裁决）**：
> "按人头平分**就是**按场地人数比例平分"——两者**等价**：
> 每人分到相同份额 ⇒ 各场地拿到的总额自然与其**劳动力人数**成正比。
> 故**不需要**按场地分别计算分红：给"劳动力"一个统一池，**按人头等分**即可。
> 对 1.0 的含义：不必为分红改造 §5.1 的 39 池；但**储蓄与代买**仍需一个统一入口（见 M4.3）。

### M4.3 劳动力储蓄 → 储蓄银行 → 购买"债券"并向金融区贷款

> **裁决（2026-09-20 第 3 次）：**"收购**走建造队列**，只是现在增加一个**金融建筑：银行（储蓄银行）**，
> 其**接受劳动力多余的资金**，用于**购买金融区发行的商品"债券"**，**向其提供贷款**。"

**这条同时回答了两件事**：① 收购仍走**建造队列**（1.0 第 27 轮的机制保留）；
② 但**出资方换成储蓄银行**——它用劳动力储蓄去买**金融区发行的债券**，从而**向金融区提供贷款**。

**机制（按裁决原文整理）**：

图示：**劳动力多余的资金 → 储蓄银行 → 购买"债券"（金融区发行）→ 向金融区提供贷款**

| 环节 | 内容 |
|------|------|
| **资金来源** | **劳动力多余的资金**（= 1.0 §5.3 的"工资结余"，但它**进入储蓄银行**，不再直接进投资池） |
| **新增建筑** | **银行（储蓄银行）**——一个新的**金融建筑**（与 §1.2-5 的"储蓄银行"对应） |
| **购买标的** | **金融区发行的商品"债券"**——金融商品的一种（新商品，进商品体系） |
| **经济含义** | 买债券 = **向金融区提供贷款**（金融区拿到现金，储蓄银行持有债权） |
| **收购路径** | 仍**走建造队列**（第 27 轮的 `Order.Acquire` 机制保留），出资方改为储蓄银行 |

**与 1.0 第 28 轮实现的冲突 → 已给出解法**：

1.0 第 28 轮实现了"**允许收购用投资池余额出资**"（`ledger.InvestmentBuyEquity`：借投资池 / 贷政府）。
但 1.0 的**投资池混入了居民储蓄**（§5.3 全额转入），所以那是"**资本用了劳动力储蓄购买**"，
与第 31 轮裁决"**资本不再能使用劳动力储蓄购买**"直接冲突。

**本裁决给出的解法**：**把"劳动力储蓄"从投资池里分出来，交给储蓄银行**——
于是"资本不得用劳动力储蓄购买"自然成立，因为那笔钱已经不在投资池里了：

| 项 | 1.0 现状（第 28 轮） | 1.2 口径（本裁决） |
|----|---------------------|-------------------|
| 劳动力结余的去向 | §5.3 两步：储蓄账户 → **投资池** | → **储蓄银行** |
| 收购的出资方 | **投资池**（第 28 轮） | **储蓄银行**（买债券） |
| 资本能否动用劳动力储蓄 | **能**（因投资池含储蓄） | **不能**（储蓄已归储蓄银行） |
| 收购是否走建造队列 | 是（第 27 轮 `Order.Acquire`） | **是（不变）** |

> **1.0 化待办（三条）**：
> 1. §5.3 的第二步从"储蓄账户 → 投资池"改为"储蓄账户 → **储蓄银行**"——
>    这会不会让投资池**枯竭**（1.0 实测投资池 3.0e9 主要来自储蓄）？需给出新的资金结构。
> 2. 新增"**债券**"的口径与记账（**不是传统商品**，见 M4.6）。
> 3. 新增建筑"**银行（储蓄银行）**"：每级雇佣、建造成本、上限、配方待定。

**资金回路（2026-09-20 第 4 次裁决澄清）**：

> "**资金会通过借贷走向金融区，再走向投资池。**"

即待办 1（"投资池会不会枯竭"）**已有答案**——**投资池由金融区补给**，回路闭合：

$$\text{劳动力多余的资金} \to \text{储蓄银行} \to \text{借给金融区} \to
\text{金融区} \to \text{投资池} \to \text{扩建/收购}$$

| 环节 | 借/贷 | 说明 |
|------|-------|------|
| 劳动力 → 储蓄银行 | 劳动力**存入**；银行**负债** | 劳动力多余资金（1.0 §5.3 的工资结余） |
| 储蓄银行 → 金融区 | 银行**放贷**；金融区**负债** | 买"债券"= 提供贷款（M4.3） |
| **金融区 → 投资池** | 金融区的（净额）**入池** | **这就是投资池的资金来源**（1.0 §4.5.1b 的"资本净额入池"） |
| 投资池 → 扩建/收购 | 投资池**支出** | G6 偿还建造力货款（§4.5.3）；收购走建造队列（第 27 轮） |

> **口径要点**：本裁定把"**储蓄**"与"**投资**"之间的中介从"直接转入投资池"（1.0 §5.3 两步）
> 改成"**经由储蓄银行放贷给金融区，再由金融区入池**"。
> 好处：① 资本不再直接动用劳动力储蓄（满足第 31 轮裁决）；
> ② 中间多了**利率**（M5 的统一利率体系）与**借贷关系**（可登记余额与利息）；
> ③ 投资池仍有来源，不会枯竭。
>
> **⚠️ 记账影响（1.0 化时必查）**：金融区从银行拿到贷款时，钱先进**金融区现金池**
> （`ledger.Capital()`），而 §4.5.1b 只把"**扣除工资后的净额**"入池；
> 若金融区的营运净额为负（1.0 实测长期为负），贷款会被**先用来补亏损**而不是入池。
> 故"贷款 → 投资池"这条通道需要一个**显式的入池规则**（否则回路看不见）。

### M4.6 "债券"不是传统商品（2026-09-20 第 4 次裁决）

> "债券**不是传统商品**，其为**借贷凭证**，标记（某处）**金融区贷款多少、每周期还多少利息、
> 多少年要还**。"

| 维度 | 传统商品（1.0 §3.1） | **"债券"** |
|------|---------------------|-----------|
| 性质 | 可消费/可投入的实物或服务 | **借贷凭证**（金融资产） |
| 是否有配方 | 有（§3.3 投入产出） | **无** |
| 是否进商品体系 | 是（`model.Goods`，含需求弹性/价格列） | **不进**——**不占商品编号、不改 `A` 矩阵维度** |
| 价格 | 由价格 ODE 内生 | 不自主波动；**面值 + 利息**（条款式） |
| 记录内容 | 数量、价格 | **贷款额 / 每周期利息 / 期限（多少年还清）** |
| 位置 | §3.1 商品表 | 一张**借贷台账**（新账户/新结构，非商品表） |

> **⇒ 这消掉了 M4.3 待办 2 的最大风险**：**"债券"不进 §3.1 商品表**，
> 因此**不会改变 `A` 矩阵维度**，**不需要重做三表联合标定**（价格表 / 谱半径 / $k$ / §8.6 的 $L^*$ 都不受影响）。
>
> **1.0 化待办（新增）**：
> 1. 设计**借贷台账**的结构：每笔"债券"记录 `{债务方=金融区, 债权方=储蓄银行, 本金, 利率, 期限, 已还本, 已付息}`。
> 2. 利息与本金偿还走 M5 的**统一利率体系**；偿还腿要与 §4.5.3 的"借贷相等"一致。
> 3. 1.2 草案 §1.2-5 的"银行每 1m 生产为 1 单位『贷款』商品、一级银行最多 50 单位"——
>    与"债券不是商品"**冲突**（那里把"贷款"当商品）。**以本条裁决为准**：贷款是**凭证**，不是商品。

### M4.4 金融区的角色变化（§3.7 的推论）

- **过渡前**：金融区 = 私有级的**所有者**（被动持有）。
- **过渡后**：金融区 = 金融商品的**买方**（链条最右端，只能从劳动力买），
  1 级工商业金融商品对应 1 级金融区。
- 与 §3.7 一致："金融区实际上是投资池收购建筑等级的**具象化**，只是中间隔了一层金融商品"。
- **过渡之后的二级交易禁跨级直连**（政府 ↛ 金融区）。
  > **歧义标注（Ⅲ）→ 已澄清（2026-09-20 第 3 次裁决）**：
  > "**资本直接承接政府 30%、劳动力直接承接资本 70%**，**这是初始化改动**。"
  >
  > 即过渡是**两条各自一跳的直接划转**（不是"政府→劳动力→金融区"的链式转让）：

| 初始划转 | 从 | 到 | 比例 |
|:--------:|----|----|:----:|
| ① | **政府** | **资本**（金融区 / 宅邸庄园） | 30% |
| ② | **资本**（金融区的 70% 私有级） | **劳动力** | 70% |

> **过渡后**：**资本 30% + 劳动力 70%**（合计 100%）。
> **"禁跨级直连 / 禁同级"只约束过渡之后的二级交易**，不约束本次初始化。

### M4.5 与 1.0 的关系（不推翻）

## M7（新设计，2026-09-20）：**工资竞标**（1.2 草案 §1.2-6 的"灵活工资"）

> **状态**：**本轮为设计稿，待讨论 → 待裁决 → 待 1.0 化**。**未改任何实现。**
> **来源**：1.2 草案原文——
> > "在原始工资的基础上，建筑扣除工资、分红后，可将**剩余部分最高 50% 投入到工资提升**之中，
> > 最后剩余的部分为扩大再生产资金。而劳动力将会**根据工资从高到低选择工作岗位**。"
>
> **本轮已在代码里确认**：`WageBid` / `工资竞` / `WagePremium` / `raiseWage` **均不存在**
> ⇒ 1.0 的雇佣调整仍是"按利润率 EMA 增/减雇"（§5.2），**不含工资竞标**。

### M7.1 目标与它在模型里的位置

**要解决的现象（1.2 草案原文）**："劳动力在约 700 周期后便会耗尽……在劳动力耗尽后，
由于没有工资系统，使得所有建筑的劳动力数量会随着人口衰减而减少。**这是不符合逻辑的**。"

**目标**：劳动力**稀缺**时，让建筑**用工资竞争**劳动力，而不是被动按利润率增减雇；
让"谁拿到人"由**出价**决定，并且**出价能力受利润约束**（不能凭空抬价）。

**位置**：它替换/增强 §5.2 的**配置机制**（谁得到多少人），但**不改变** §5 的**工资表**
（各阶级的**基准**工资不变）。即：**基准工资（契约层）+ 竞标溢价（每场地每周期）**。

### M7.2 每 tick 的规则（5 步）

新增状态：每场地 `WagePremium_i ≥ 0`（元/人/周期）。

**第 1 步｜基准工资**
$$\text{baseWage}_i = \text{WagePerLevel}(i) / \text{LaborPerLevel}(i)$$
（1.0 已是逐建筑：城镇 6.75、农业 5.65、庄园 5.65、金融区 6.75。）

**第 2 步｜可竞标资金（A_i）**
$$\pi_i^{net} = \text{本期纯利} - \text{baseWage}_i \times \text{在岗人数},\qquad
A_i = \text{wageBidCap} \times \max\left(0,\ \pi_i^{net}\right)$$
`wageBidCap` **默认 0.5**（1.2 草案原文"最高 50%"）。

> **⚠️ 与 §4.5.1 的关系（必须写明，否则会重复扣一次工资）**：
> §4.5.1 的划分顺序是「**先补足自身现金池 $C^*_i$，余额再按持股分红**」。
> 竞标资金应当取自**分红之后的剩余**（即"扩大再生产资金"那一份），
> 而不是在分红之前再切一刀。故上式的"本期纯利"应理解为
> **"扣基准工资与分红后的剩余"**，与草案原文"建筑扣除工资、分红后"一致。

**第 3 步｜出价与择优（本期只抬一次，避免与利润互为因果的震荡）**
$$p_i^{new} = \min\left(p_i^{max},\ p_i + \frac{A_i}{\text{在岗人数}}\right)$$

- **抬价条件（待裁决①已定：(a)）**：**只在该场地本期招不满**（申报量未被满足）时才抬价；
  **招满则不加价**（否则会无谓地推高成本）。
- **回落与衰减（待裁决②已定：(b)+(c)）**：两条同时实施——
  - **(b) 招满即回落**：本期**招满且有富余申报**（说明出价过高）⇒ 溢价按 `wageBidDecay` 下调；
  - **(c) 缓慢衰减**：即使一直缺员，溢价也按 `wageBidDecay` 向 0 衰减，
    使"降价试探"成为可能（否则只有上抬、没有下探）。
  - **`wageBidDecay` 默认 5%/年**（年化口径，与 §5.2 的 `HireAnnual = 5%/年` 同一约定，
    每 tick 生效 $5\%/52 \approx 0.096\%$）。
- **不设显式上限（待裁决⑤已定：(c)）**：$p_i^{max} = +\infty$，
  由 **§4.1 的 10% 阈值隐式约束**——抬价推高成本 ⇒ 利润率跌破阈值 ⇒ 停建、亏损解雇，
  竞标资金 $A_i$ 随之归零。**故不需要额外的工资上限条款**。

**第 4 步｜配置（按工资从高到低）**
1. 各场地按**实际人均工资** $w_i = \text{baseWage}_i + p_i$ **降序**排序；
2. 每级建筑需要 `LaborPerLevel` 人；**雇佣率 $h_i$ 按 §5.2 的规则演化**
   （利润率 > 0 尝试增雇、< 0 解雇）——**竞标只决定"优先级"，不决定"要不要人"**；
3. 依次满足：$\text{需求}_i = N_i \times h_i \times \text{LaborPerLevel}$，直到总人口耗尽；
4. **未获配的申报量 ⇒ 该场地雇佣率按实际到岗/申报的比例下调**（与 1.0 第 23 轮的
   `LaborMarketRatio` 同构，但那时是**全局等比**，这里是**按工资排序**）；
5. 仍有人口剩余 ⇒ 按 §4.2 的就业顺序进自给农场，再余为失业。

> **迁徙成本（待裁决④已定：无迁徙成本）**：工人**瞬时**按工资排序择业，
> **不设迁移摩擦、不设每期迁移上限**——因为模型里工人本来就没有"地点"这个状态，
> 只有"场地 × 阶级"的池（§5.1）；引入摩擦需要一个额外的人口分布状态，本版不引入。
> 于是**排序即配置**：同一 tick 内按工资降序分配完毕。

> **失业者参与竞标（待裁决⑥已定：(a) 参与）**：失业人口在 §5.1 的失业池里，
> 他们**就是被高价吸引的那部分劳动力**，故参与排序与配置；一旦被某场地录用，
> 当 tick 即从失业池转入该场地的池。

**第 5 步｜分阶级落到人群池**
- 场地 $i$ 的阶级 $c$ 的**实际工资** = $\left(\text{baseWage}_i + p_i\right) \times
  \dfrac{\text{该阶级的基准工资}}{\text{baseWage}_i}$
  （即**溢价按比例放大到各阶级**，保持 75/20/5 的工资结构）；
- 人群池由"场地 × 阶级"扩展为**携带实际工资**的池（§5.1 的 39 池结构不变，
  但每池多一个 `Wage` 字段）。

### M7.3 与价格/成本的耦合（必须处理，否则竞标会自我引爆）

实际人均工资进入单位劳动成本，进而进入 §3.4 的零利润价：

$$l_j = \frac{\text{baseWage}_j + p_j}{q_j} \times \text{LaborPerLevel}$$

- 1.0 的 `refreshPzero()`（当期零利润价 $P^0(t)$）**要改用实际工资**；
  否则钳制带与 A1/A3 判据仍看"无溢价"的成本，会把高工资部门的贴边误判。
- **静态 $P_{ref}$ 不变**：它由 §3.4 的 Leontief 方程在**基准工资**下解出，
  竞标只影响**当期**成本与价格动态（与第 14 轮"$P_{ref}$ 固定、$P^0(t)$ 动态"的分工一致）。
- **自限机制（这是本设计的核心好处）**：抬价 ⇒ 成本↑ ⇒ 利润率↓ ⇒
  ① 分红与竞标资金↓（$A_i$ 变小）、② 低于 §4.1 的 10% 阈值就不再扩建、③ 亏损就解雇。
  ⇒ **工资竞标天然被利润约束**，不会无限抬价。

### M7.4 记账

$$\text{借 建筑}[i]\ \ \text{溢价总额}\ (p_i \times \text{在岗人数})
\qquad
\text{贷 人群池}[i][c]\ \ \text{按阶级分摊}$$

- 溢价是**工资的一部分**，故与 §5.1 的工资划转**同一笔交易**（一次过账，不新增腿）；
- **基准工资的腿不变**，只是金额从 `baseWage × 人数` 变成 `(baseWage + p_i) × 人数`；
- **货币总量不变**（建筑 → 人群池的转移）；
- **与投资池的竞争关系**：$A_i$ 从"扩大再生产资金"里划走 ⇒ **投资池入池额减少**。
  即"抬工资"与"扩建"花的是**同一笔钱**——这是本设计想要的政策张力。

### M7.5 与 1.0 现有机制的差异（一张表）

| 维度 | 1.0 现状 | M7 工资竞标 |
|------|---------|------------|
| 谁决定"谁拿到人" | §4.2 就业顺序（生产建筑 → 自给农场 → 失业）+ 全局等比配给（第 23 轮 `LaborMarketRatio`） | **按实际工资降序**（工资高者优先） |
| 工资 | 契约固定（逐建筑结构表） | **基准 + 每场地每周期溢价** |
| 雇佣量 | §5.2 按利润率 EMA 增/减雇 | **不变**（竞标只改"优先级"，不改"要不要人"） |
| 溢出人口 | 按比例分摊到各场地 | **落在工资最低的场地**（被挤出） |
| 与投资的关系 | 剩余全部入投资池 | 剩余**最高 50%** 先用于抬价，其余入池 |

### M7.6 裁决结果（2026-09-20 第 5 次裁决：**已全部裁定**）

| # | 问题 | **裁决** | 落地要点 |
|:-:|------|---------|---------|
| ① | 溢价是否只在招不满时才抬 | **(a) 只在缺员时抬** | 招满不加价，避免无谓推高成本 |
| ② | 溢价能否下调 | **(b)+(c) 招满即回落 + 缓慢衰减** | 新增 `wageBidDecay`，**默认 5%/年**（年化，与 `HireAnnual` 同约定） |
| ③ | 分红与竞标的先后 | **(a) 先分红再竞标** | $A_i$ 取自"扣基准工资与分红后的剩余"，与草案原文一致 |
| ④ | 工人迁徙成本 | **无迁徙成本** | **瞬时按工资排序择业**，不设摩擦与迁移上限（模型里工人无"地点"状态） |
| ⑤ | 单级工资上限 $p^{max}$ | **(c) 由 §4.1 的 10% 阈值隐式约束** | **不设显式上限**；抬价 ⇒ 成本↑ ⇒ 利润率跌破阈值 ⇒ 停建/解雇 ⇒ $A_i$ 归零 |
| ⑥ | 失业者是否参与竞标 | **(a) 参与** | 失业者就是"被高价吸引的人"；录用当 tick 即从失业池转入场地池 |

**⇒ M7 的设计参数已齐**，可直接进入"1.0 化"（补实测证据 / 前值→后值 / 验收判据）与实现。

**新增参数（M7 引入，均为 1.2 侧）**：

| 参数 | 默认 | 含义 |
|------|:----:|------|
| `wageBidCap` | **0.5** | 剩余利润中可投入工资竞标的**比例上限**（草案原文"最高 50%"） |
| `wageBidDecay` | **0.05/年** | 溢价的衰减率（每 tick $0.05/52$）；招满时触发、缺员时也缓慢生效 |

> **与 1.0 的纪律一致**：`wageBidEnabled=false` 时必须**逐位复现** 1.0 现行行为

## M8（新设计，2026-09-20）：**借贷台账**（债券的字段、利息、偿还、以及入池规则）

> **状态**：设计稿，**待 1.0 化**。**未改任何实现。**
> **来源**：R58 第 2 条（"债券不是传统商品，是借贷凭证"）+ 本轮裁决（"本金 500k、

### M8.1 债券的字段（一笔贷款 = 一条台账记录）

| 字段 | 值 / 含义 |
|------|----------|
| 债务方 | **金融区**（`ledger.Capital()`）；**农业侧不参与**（宅邸庄园不借贷，见 M8.6 ④） |
| 债权方 | **储蓄银行**（M4.3 的出资方） |
| **本金** `P` | **500,000 元** |
| **利率** `r` | **年化 5%** |
| **期限** `N` | **5 年**（= 260 周期） |
| **还款方式** | 等额本息（见 M8.2），每周期还一次 |
| 已还本 `paidPrincipal` | 累计已偿还本金 |
| 已付息 `paidInterest` | 累计已付利息 |
| 余额 `outstanding` | `P − paidPrincipal`；归零即结清、台账记录移出 |

### M8.2 每周期还款额（等额本息）

年化 5% 按月/周期复利，5 年 = **260 周期**：

$$i = \frac{0.05}{52},\qquad
A = P \cdot \frac{i\,(1+i)^{260}}{(1+i)^{260}-1}
= 500{,}000 \times 0.00436536 = \mathbf{2{,}182.68\ \text{元/周期}}$$

| 项 | 数值 |
|----|-----:|
| 每周期还款 `A` | **2,182.68** |
| 其中利息（首期） | 480.77 |
| 其中本金（首期） | 1,701.91 |
| 5 年总还款 | 567,497 |
| 总利息 | 67,497（≈ 本金的 **13.5%**） |

> **为什么不用"每期还本金 $P/260$ + 当期利息"**：那会让前期还款额更高（首期 2,403.85），
> 且总额不同。**等额本息**是商业贷款的通行做法，也让"每周期一笔固定金额"在账本上更干净。

### M8.3 资金流与记账（本轮裁决的落点）

> **裁决**："**将贷款记在金融区头上，然后投入投资池**。"

**⇒ 资金**不经过金融区的营运现金池**，直接进投资池**；**负债**记在金融区头上。三者分开：

| 腿 | 借贷 | 说明 |
|----|------|------|
| **① 放贷** | **借 储蓄银行 / 贷 投资池** | 钱从储蓄银行**直接**到投资池 |
| **② 负债登记** | 金融区**负债 +P**（**非现金科目**） | 记在金融区头上；**不进它的营运现金池** |
| **③ 每期还款** | **借 金融区 / 贷 储蓄银行**（本息合计 A） | 需先给金融区一条**资金来源**，见 M8.4 |
| **④ 利息收入** | 储蓄银行持有；**当期**分配给**劳动力**（它是劳动力储蓄的代理，M4.3；已裁决见 M8.6 ③） |

> **为什么不让钱先过金融区的现金池**：1.0 实测金融区营运净额**长期为负**（它承担全行业
> 30% 亏损的对应份额）；若贷款先进它的池，会被**先拿去补亏损**而进不了投资池——
> 这正是我上一轮标出的记账风险。**本裁决把它绕开了**：
> 资金直连（储蓄银行 → 投资池），负债单独登记在金融区头上。
>
> **⚠️ 但这引入一个必须补的前提**：**1.0 没有"非现金科目/资产负债表"**——
> §4.5.1 的所有权是**持股比例**（`GovLevel/PrivLevel`），`ledger` 里只有**现金池**。
> 故"负债登记"需要一个**新结构**（例如 `Capital.Debt` 字段，或新增 `ledger.KindDebt`），
> 且**不得**参与 §4.5.3 的"借贷相等"（它不是资金腿），也**不得**计入 §7 的 GDP 存量口径
> （否则会把一笔贷款算成财富）。

### M8.4 还款的资金来源（**已裁决：(a)**）

**裁决（2026-09-20 第 6 次）**："**金融区在入池之前先扣下本期还款额**"。

即在 §4.5.1b 的入池计算里加一条"**先还贷**"：

$$\text{入池}_f = \max\left(0,\ (\text{非农生产建筑的私人份额纯利} - \text{金融区工资}) - A\right)$$

其中第一项括号内是 §4.5.1b 的**净额**，$A$ 是**本期应还本息**（先扣，还储蓄银行）。

**金融区净额 → 先还本息 → 还款给储蓄银行 ＋ 余额入投资池**

| 优点 | 说明 |
|------|------|
| **谁借谁还** | 还款出自金融区自己的净额，不由投资池或政府代偿 |
| **自动回收** | 每周期回收 2,182.68，**5 年后债务自然归零** |
| **维护货币循环** | 钱从金融区 → 储蓄银行 → 再放贷，形成闭环（M4.3 的回路） |
| **不加重政府赤字** | 政府不参与（1.0 已实测国库贴在上限上，见 R50） |

> **⚠️ 一个必须写明的边界**：若金融区当期净额**不足以**支付 A（1.0 实测其营运净额
> 长期为负），则本条会导致**入池_f 为 0**（本就为 0）且**欠款累积**。
> **违约规则已裁决（2026-09-20 第 7 次）：违约则延期**——见 M8.4.1。

#### M8.4.1 违约规则：**违约则延期**（已裁决）

**裁决原文**："**违约则延期**"。

**规则**：当期能付多少付多少，**付不出的部分不核销、不加速、不没收**，
而是**滚入未偿余额**，并按同一利率 **5%/年** 继续计息（**复利展期**）：

$$\text{outstanding}_{t+1} = \text{outstanding}_t \times (1 + i) - \text{本期实付}$$

其中 $i = 0.05/52$、**本期实付 = min(应付 A, 金融区当期净额)**。

| 情形 | 处理 |
|------|------|
| 净额 ≥ A | 正常还本息，台账按 M8.2 推进 |
| 0 < 净额 < A | **部分支付**；差额滚入 outstanding（**延期**） |
| 净额 ≤ 0 | **本期实付 = 0**；全额滚入 outstanding 并计息（**延期**） |

**三条必须写明的边界**：

1. **没有"破产/没收"机制**——1.2 不引入资产清算、不没收股权、不加速到期。
   债务只能靠**未来的净额**慢慢还（或永远还不上，见下）。
2. **期限语义变成"最短期限"**：M8 的"5 年"是**无违约情形下**的期限；
   一旦延期，实际结清时间后移。**账本上仍记录"原始期限 5 年 + 已延期次数/金额"**，
   以便诊断（这与 1.0 §0.4 第 2 项"债务上限只按建造力产出计价"是同一个量级问题的两端）。
3. **与 A7 判据的关系（1.0 侧影响）**：若金融区永远还不上，这条不是问题（它是**资本**的债务，
   不是政府的）；但若将来把"储蓄银行的债权"计入某个总量，就会与 §8.4 的 A7（政府债务上限）
   产生口径交叉——**故必须明确：M8 的债务记在金融区头上，不计入政府债务**。

### M8.5 与 M5（统一利率体系）的关系（**已裁决：无息例外取消**）

**裁决（2026-09-20 第 6 次）**："**年化 5%，将无息去掉**"。

- M8 的利率（年化 **5%**）即 M5 统一利率曲线上的**基准利率**；
- **1.2 草案 §1.2-7 的"投资池可获得 5 年无息贷款"作废**——该条应改为
  "投资池可获 **5 年、年化 5%** 的贷款"，与 M8 同一台账口径；
- ⇒ **M5 的四条腿（政府债务 / 央行→银行 / 银行→其他建筑 / 投资池融资）全部 5%，无特例**。
  这消掉了我上一轮标出的"唯一例外"问题。

### M8.7 负债登记的实现形态：**已裁决选 (A) `Capital.Debt` 字段**

**裁决（2026-09-20 第 8 次）：选 (A)。**

**背景**：1.0 的 `ledger.Auditor` 里**只有现金余额**——`Total()` 的定义就是
"全部账户余额之和 = 货币总量"，所以**任何进 `balances` 的东西都会被算成货币**，
而负债不是钱。

| 维度 | **(A) `Capital.Debt` 字段** | **(B) `ledger.KindDebt` 账户** |
|------|---------------------------|------------------------------|
| **性质** | 挂在 `fiscal.Capital` 上的一串**非现金标量** | 账本里的一类**账户**，有余额 |
| **结构** | `Capital.Debt []Loan`（每笔贷款一条：本金/利率/期限/已还本/已付息） | 每笔贷款一个 `Account{Kind: KindDebt, Index: i}` |
| **是否进 `Auditor.balances`** | **否**——完全不进那张表 | **是**（除非专门排除），于是**会被 `Total()` 算进货币总量** |
| **与货币守恒（§4.5.3）** | **天然无关**；不会污染 A8/货币总量 | **必须显式排除**：`Total()`、`TotalOf()`、借贷相等、GDP 存量口径**四处**都要加白名单 |
| **能否多笔** | 能（切片，天然支持 1 笔 = 1 条台账） | 能（一账户一笔），但**账户数会随贷款笔数膨胀**，账本规模无界 |
| **与 1.0 现有结构的一致性** | **高**——1.0 已经把"持股"（`GovLevel/PrivLevel`）做成 **BuildingState 的字段**，而不是账本科目；负债是同类东西（**所有权/债务 = 标量，不是资金**） | **低**——1.0 的 `AccountKind` 全是"钱放在哪"，没出现过"钱的对手方" |
| **报表** | 需要新增报告项（`Capital.Debt` 汇总） | 天然出现在账本遍历里（但要小心被当成钱） |
| **实现成本** | 低（加字段 + 台账推进逻辑） | 中（要改 `Total`/`TotalOf`/审计四处，风险面大） |
| **风险** | 低：不可能破坏货币守恒 | **高**：一处漏排除 ⇒ 货币总量虚增 ⇒ A8 判据假失败或假通过 |

**这条区分的本质**：

- `ledger.AccountKind` 回答的是"**这笔钱在谁手里**"；
- **负债回答的是"欠了多少"**，它是**权利/义务**，不是持有物。

1.0 已经做过一次同样的选择：**持股没有进账本，而是做成了 `BuildingState` 的字段**。
M8 的负债与持股同族（都是"所有权/债权"），**因此应当沿用同一做法**。

**已裁决：选 (A) `Capital.Debt`**，理由三条：

1. **不污染货币守恒**——它根本不进 `Auditor.balances`，A8 与"货币总量"零风险；
2. **与 1.0 既有设计同构**（持股也是字段，不是账本科目）；
3. **实现面小**：只在 `fiscal.Capital` 加台账 + 在 `step` 的入池/还款处推进，
   不动 `ledger` 的四个不变量检查点。

**落点（1.0 化时按此实现）**：

| 项 | 内容 |
|----|------|
| 结构 | `fiscal.Capital` 新增 `Debt []Loan`；`Loan{Principal, Rate, Term, PaidPrincipal, PaidInterest, Outstanding, Deferrals}` |
| 推进位置 | `sim.step` 的 ⑧（资本入池）之前：**先按 M8.4 扣本期还款额**，不足则按 M8.4.1 **延期**（滚入 `Outstanding` 并按 5%/年计息） |
| 记账腿 | 放贷：**借 储蓄银行 / 贷 投资池**；还款：**借 金融区 / 贷 储蓄银行**（两笔都是普通资金腿，参与借贷相等） |
| **不进**的地方 | `Auditor.balances`、`Total()`、货币守恒（A8）、§7 GDP 的存量口径、§8.4 的 A7（政府债务） |
| 报表 | 新增诊断项：金融区未偿余额 / 已付息 / 延期次数 |

> **若将来需要"债权的持有方"也表达出来**（例如储蓄银行把债权再卖给第三方），
> 那才需要把 (B) 引入——那时应当**新增一个独立的表**（如 `ledger.DebtBook`），
> 而**不是**把负债混进现金账户表。

## 1.2-1 总述与阶段目标

货币与金融是模拟经营类游戏不可绕过的一个部分。好的货币与金融系统会在可玩性的基础上达到拟真的效果。维多利亚3至今都没有做出相对拟真的货币与金融系统，希望叶赫那拉能够在巨人的肩膀上走的更远。

本阶段将引入基础货币系统、实现基础货币功能即结算功能、引入金融业、引入投资池概念、引入金融商品概念、优化投资系统。

## 1.2-2 货币的三种形态与银行

货币，是一种特殊的商品，根据定义，其为人类可接受的一般等价交换物。货币具有多种形态，不幸的是，维多利亚时期正是处于实体货币向可兑付以及不可兑付货币变化的过渡期。为了相对拟真的模拟这一概念，不可避免的要引入至少三种货币结算模式——贵金属货币、可兑付货币、以及信用货币。

其中为了简化开发，我们设置贵金属本身设为锚定物，其中贵金属货币由其成色决定其发行量与价值；可兑付货币由准备金率决定其发行量与货币；信用货币由货币政策本身决定其发行量，由市场流通货物价值决定其价值。

这三种货币政策由银行建筑以不同的生产模式落实。银行购买贵金属（信用货币除外），生产货币，货币本身加入银行现金池，而银行将通过借贷的形式将货币转移给其他建筑。其中金融区便是最主要的用户之一。

这种特殊的功能使得银行建筑成为特殊的建筑。尽管其生产的货币理论上是商品，但货币如果真正制作为一种商品，当前基于货币定义的商品星系就会瞬间因为循环定义而崩塌，故而货币不能作为一般商品进入商品页面。

当前版本我们将注重于贵金属货币的开发，用于完善货币系统；更加复杂的货币系统将随着2.2版本金融补完而开发完成。

## 1.2-3 货币系统带来的问题

由于货币系统的到来，产生了海量的新问题：利润与再生产、工资与消费、商品价格的表示、货币的转移等等。

### 3.1 商品价格的表示

首先要解决的肯定是商品价格问题。当前的商品价格是微分方程的直接解，如果引入货币概念，则需要借助货币与贵金属价格之间的关系为原商品价格乘以一个系数。这个关系则是与银行货币发行政策有关的：我们设置贵金属货币的成色是其理论价值的五成（即通过成色、法定等因素强行抬高贵金属货币的含金量），则货币价值为贵金属价值的一倍。此时商品价格就转变为商品相对于贵金属的比值乘以货币与贵金属的比值。

为了区分银行的职能，我们将银行分为三类：中央银行、储蓄银行、投资银行（工商银行）。每种银行的职能与收支来往是固定的，方便逻辑编写。

如假定1单位黄金的价格恒为10,000，则每单位中央银行每周期收购20单位黄金，生产200,000货币。这些货币全部转入中央银行的现金池中。

储蓄银行与工商银行的功能需要重置工资与利润后才可实现，目前不讨论。

### 3.2 货币的转移与结算

其次就是货币的转移问题，当前对于购买商品时的货币支付问题相对不清晰，现在明确——每一单位的商品转移都需要有投资池之间的划账，每一单位的商品都要按照市场价格支付。这一支付发生在交易关系双方的投资池之间。

### 3.3 劳动力与工资

劳动力由于当前没有自己的动态工资，故而以修正参数的形式参与到市场活动中来，这一关系将被新的工资体系取代。劳动力将按照工种与所在生产建筑区分收入，其收入汇入对应阶层现金池下，并根据不同收入等级加权进行统一消费品购买。

### 3.4 利润与再生产

既然有了货币与购买关系，那么同样的就出现了利润与再生产。生产建筑通过买入原料卖出成品，获得毛利收入。这一部分收入将划分为工资、分红、与再生产利润。其中工资部分直接汇入对应劳动力的阶层现金池；分红则为建筑所有者的额外利润百分比分配，如一个厂为资本家所有，则该周期该建筑营业利润的10%再汇入资本家现金池；再生产利润则是扣除上述两者后的留存收益，优先填满每级建筑的500,000现金池，随后全部转入投资池。

### 3.5 投资池

为了实现相对正常的扩大再生产，1.2版本将引入维多利亚3的投资池概念。即所有建筑共用同一个投资池，使扩大再生产的成本全部由统一的投资池支付，而投资池的建设顺序由阶层的投资池贡献力与对应的投资倾向综合形成。

### 3.6 金融商品

为了更加精细的模拟市场收购行为，1.2版本将翻倍商品的数量——每种生产建筑将发行自己的金融商品，这一商品对应的是生产建筑单位等级的收益权，对应商品的所有者将获得每周期的对应分红。对应的，金融区将成为金融商品的主要购买者。

### 3.7 金融区

金融区是相对庄园的被动金融建筑。每一级工商业等金融商品都对应着一级金融区（农业建筑则是对应庄园）。金融区实际上是投资池收购建筑等级的具象化，只是中间隔了一层生产建筑的金融商品。目前版本将会将金融商品的价格根据建造力对应为随建造力波动的价格而非自主波动的价格。且金融商品只能被顺序交易若干次：政府所有-劳动力所有-金融区所有。各等级平级无法发生交易。

由于交易是长期发生的，故而交易成本不会计入投资池选择交易的考虑范围。

## 1.2-4 玩家现金池

由于货币系统上线，添加玩家现金池（即现金储备池/贷款池）。

## 1.2-5 贵金属与银行的具体设定

贵金属由金矿生产（实际上银矿与铜矿也会加入这一行列，但目前不添加）。金矿劳动力需求5k，比例同一般矿场。单位金矿消耗15煤炭、15工具，生产25黄金。

1.2版本最多建造50级金矿。

金融区、银行与中央银行每级雇佣1k人，其中500人为资本家，500人为劳工（工资按先前分层）。

单位中央银行消耗20黄金，生产400,000货币进入现金池。其中一半用于支付10,000原每单位黄金给金矿。剩余部分进入中央银行现金池。当黄金有剩余时，中央银行自动扩建。

贷款。贷款是一种金融活动，以中央银行-银行-其他建筑的顺序进行，前者向后者贷款，每次贷款调拨金额100w元，即通过计次计算贷款数量。贷款不得超过目标建筑现金池100%，即一次贷款的抵押率至少50%。

每级中央银行生成一级银行。1.2版本将中央银行现金池与银行现金池共用。银行向其他建筑提供贷款。

## 1.2-6 工资系统

由于目前系统已经可以运行，而根据运行经验，劳动力在约700周期后便会耗尽（取决于初始建筑数量——启动速度，与总劳动力数量——终点距离）。在劳动力耗尽后，由于没有工资系统，使得所有建筑的劳动力数量会随着人口衰减而减少。这是不符合逻辑的。

为了模拟劳动力在劳动力短缺的情况下的自由选择权，需要加入工资系统。即在原始工资的基础上，建筑扣除工资、分红后，可将剩余部分最高50%投入到工资提升之中，最后剩余的部分为扩大再生产资金。而劳动力将会根据工资从高到低选择工作岗位。

## 1.2-7 其余设定

银行每1m生产为1单位“贷款”商品，一级银行最多生产50单位“贷款”。当资金池超过对应数量时银行自动扩建。

投资池可以在"不足以支付当前建造力所需200%资金"的情况下获得5年的"贷款"，在5年后结清。
