叶赫那拉市场 · 由 1.1 前端设计.md 经 VC_Go/tools/md2html.js 离线编译生成 · 完全自包含，无需联网

性质：本文件是 docs/1.1 图形化界面.md（1.1 契约 v1.0）的设计规格， 不是契约本身。与契约冲突时以契约为准；本文件只负责把契约的条款落成可实现的界面决策。 约束（全部来自契约，不得违反）： ① 技术栈 = HTML，自包含（无 CDN、无 npm、无网络请求、无构建步骤）； ② 字体 = 根目录 MingChinese.ttf，字号 20（经 @font-face 加载）； ③ 渲染 60 FPS，逻辑默认 1 tick/s、档位 ×0/×1/×2/×5，N = 60 ÷ (tick/秒)； ④ 四个一级菜单：市场 / 建筑 / 建筑队列 / 其他； ⑤ 队列页每页 20 条；拆除核销带符号额；玩家动作立即生效。

一、设计目标与三条原则

目标：兼顾好看（一眼看出系统在往哪走）与实用（每个格子都能追到唯一字段）。

#原则为什么（来自本项目的实测教训）
P1同一屏内必须有"名义 vs 实际"对照1.0 长跑实测：价格指数 ×9.9e4、名义货币 3.2e7、名义 GDP 2.6e13，而居民实际货币余额从 6.7e6 掉到 319。只看名义会把恶性通胀读成高速增长
P2状态色必须区分"健康/告警/越界"，且不能只靠颜色A2 的 ±450% 上限恒真、A6 靠增长豁免短路——判据本身会撒谎，界面必须把原始量摆在前面（贴边率、亏损占比、债务÷上限、实际增加值斜率）
P3不做假数据、不做占位图表契约 §0.2d 已载明"不得显示仓库纯利"（份额按设计固定为 0）。空数据要显式写"无数据"，不能用平线假装

四、组件规格

4.1 指标卡（Metric Card）

用于"其他"页的 4 张卡与顶栏。结构：标签（--ink-2, 16px） / 数值（20px, tabular-nums, 按状态着色） / 副行（环比或占基期比例）。

  • 负值必须着色 + 加方向符号（▼），不能只靠颜色（P2）；
  • 数值超长时缩位（万/亿/万亿），但悬停显示精确值。

4.2 数据表

  • 表头吸顶；数值列右对齐；状态列用色块 + 文字双重编码；
  • 排序：点表头切换升/降；排序列不改变分类色（§2.1）；
  • 行内迷你条（bar-in-cell）：用于贴边率、亏损占比这类 [0,1] 量，长度即数值，比数字更快读出。

4.3 图表（三类，够用即可）

类型用在哪规格
多序列折线价格史、GDP 史、人口、幸福度、货币存量最多 8 条；图例可点选隐藏（契约 §4.1 要求）；基准线（=1、=0）用 --neutral 虚线
堆叠面积实际增加值分部门（农业/工业/自给农场）用于看"结构变化"，比三条独立折线清楚
饼图阶级比例、阶级现金池仅 2 个（契约 §四-4 冻结）；> 6 片时改用横向条形

坐标轴规则：价格类用对数轴（1.0 实测价格跨 6 个数量级，线性轴会把早期全压成 0）； 金额类用线性轴但标注缩位单位；时间轴固定按 tick，不按帧（契约 §五）。

五、四个页面的落地

5.1 市场页（契约 §4.1）

左：商品二级菜单（14 项 + 图例开关勾选框）。右：详情 = 名字 / 现价 / 两个相对价分行 （P/P⁰ 与 P/Pinit——契约 §二 明确要求分开命名，不可混为一谈）/ 生产量 / 消费量。 下：近期图（末 60 tick）与全期图（全程）。 最底：全商品总价格图（通栏，各商品固定色，经二级菜单可取消显示）。

必须加的一格：详情里要并列 工资总额 / 消费支出 / 结余入池。 原因：1.0 已删除"全部工资用于消费"，且 σ_save 默认 1 —— 只看"消费量"会把储蓄渠道误读成"没人买东西"。

5.2 建筑页（契约 §4.2）

全部生产建筑（含自给农场）+ 逐行：名字 / 数量（含扩建中）/ 雇佣率 / 现金池 / 利润率， 右侧 x1/x5/x10 的建造与拆除按钮。

  • 原材料不足红字：判据 = produce 的配给比 < 1（契约 §0.5-U2），不用 MarginEMA < 0；
  • 现金池允许为负（1.0 实测政府池可到 −1.85e12），负值用 --down 且不得显示为 0；
  • 拆除按钮需二次确认并显式提示"资产与货币一并核销、在途订单不退款"（契约 §0.2-7）。

5.3 建筑队列页（契约 §4.3）

每页 20 条，左右键翻页，标注页数。每条：建筑类型 / 已建部分 ÷ 总建造力（进度条）/ 剩余时间。置顶按钮仅对玩家可置顶的条目可用（契约 §0.2-6 的优先级：玩家 > 预警插队 > FIFO）。

5.4 其他页（契约 §四-4，栏目已冻结）

① 4 张指标卡 → ② 8 列市场对照表 → ③ 历史曲线组。 （参照侧的"物流两栏"明确不做——1.1 无库存/运输，归 2.0。）

  • 硬约束：不得显示仓库纯利；
  • 阶级比例饼图按固定阶级切，并在图注注明"与工资表口径的差异"（契约 §四-4）。

六、60 FPS 的三条实现义务

  1. 永不整表重建 DOM：数据每 tick 变化，但节点复用（keyed update）。14 商品 × 8 列 ≈ 112 格， 每 tick 全量 innerHTML 重建会在 ×5 档（12 帧/周期）掉帧。
  2. 图表用一次绘制的 <canvas>，不用 112 个 SVG 节点；仅在数据变化时重绘。 （契约要求"无网络请求"，canvas 是原生能力，不引入依赖。）
  3. 帧与 tick 解耦：渲染循环 requestAnimationFrame 恒定 60 FPS； tick 由累计帧数触发（N = 60 ÷ (tick/秒)）。绝不让帧率或倍速改变 tick 序列—— 1.0 刚在 ledger.sortedAccounts() 修好"同二进制逐位一致"，帧驱动 tick 会重新打破它。

# 然后浏览器打开 http://localhost:8787/

#问题现象结论（已修正/需注意）
V1flex 子项被压缩一级菜单 <nav> 在 flex 行里宽度被压缩，市场 竖排成"市/场"侧栏必须写 flex:0 0 200px + white-space:nowrap。这类问题读规格发现不了

10.1 由 V4 定下的两条硬规则（写实现时必须遵守）

规则内容为什么
R-scale轴范围不得依赖可见性。范围由全量数据算一次；隐藏某条序列只移除该条线的像素，不动网格、不动刻度、不动坐标映射否则"隐藏一条线"会被读成"剩下的线变陡了"——这是误导，不是缩放。若将来要提供"聚焦模式"，必须做成显式开关并提示轴已变，不能因隐藏而隐式发生
R-zero防零除必须用相对量：`mx = mn + (mn

10.2 这条 bug 的验证方法（已固化为脚本）

因为轴刻度是画在 canvas 上的文字、无法从 DOM 读出，所以实现里把本次比例尺同时写进 canvas.dataset（data-ymin / data-ymax / data-ticks），自检脚本即可从 --dump-dom 读取：

powershell -ExecutionPolicy Bypass -File tools\verify_scale_freeze.ps1

它的做法是：对 ?hide= 取 0/1/5/9/13 五种隐藏数各 dump 一次 DOM， 比较三个 data-*。冻结成立当且仅当不同隐藏数下比例尺只有 1 种。实测输出：

case       legend-on   ymin   ymax   ticks
hide-0     14          相同    相同   0.91|30.73|1,039|35,108|1.19e6
hide-1     13          相同    相同   同上
hide-5     9           相同    相同   同上
hide-9     5           相同    相同   同上
hide-13    1           相同    相同   同上
distinct scales = 1   RESULT: PASS
