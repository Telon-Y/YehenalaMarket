## 三、对 1.0 判据的已知影响（必须作为 1.1 的前置裁决）

**A8 必须开显式例外。** 1.1 的"拆除 = 资产与货币一并核销"会销毁货币，故
契约 §8.4 :1854 的 `ΔM == NewCapital + 诊断注入` 须改为：

```
ΔM == NewCapital + Infusion − Δ(累计核销)
并且：未申报的货币减少（残差 < 0 且不属于申报核销）仍然判为违规
```

**这不是单纯的放宽**——1.0 的 A8 是**构造性恒真**（两侧同源 `TotalMoney`，
`report.go:330-341`，判别力 ≈ 0，见 `docs/verdict/1.0 验收判决书.md` §二-2.3），
加上申报口径后它能区分"**申报核销**"与"**漏记一条腿**" ⇒ **判别力比 1.0 更强**。

**另一处必须保持**：§4.4 建筑自动缩编**保持冻结**（`DecayFrozen=true`），
拆除由玩家手动触发；**不得**为拆除而翻回 `false`（会同时改变 AI 侧行为）。

## 四、1.1 已识别出的两处口径陷阱（讨论阶段的实质产出）

1. **"商品相对价格"有两个**：docx 原文写"相对**初始**价格百分比"，
   而代码里 `PriceRatio` 是 **P/P⁰（相对当期零利润价，随成本漂移）**。
   ⇒ 契约必须分别命名并标注，否则界面与判据会互相误读。
2. **"市场消费（期望消费）数量"**：1.0 已**删除**"全部工资用于消费"（§0.4 第 15 项），
   且 §5.3 储蓄渠道默认 **σ_save = 1**（结余全额转入投资池）。
   ⇒ "消费支出"与"工资总额"差距很大，总表必须**并列**显示**工资总额 / 消费支出 / 结余入池**三项。

另有一处**数据口径不一致**需在写 UI 前定：`cohort.go:141` 的财富档用**固定阶级工资带**
`{5,10,20}`，而农业与庄园有**自己的阶级结构**（`{5,7,10}`）
⇒ "阶级比例饼图"按哪个维度切必须指定（**建议按 `Pools[].Class`** 并注明与该工资带的差异）。
