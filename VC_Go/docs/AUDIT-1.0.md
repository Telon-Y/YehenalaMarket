# 1.0 验收审计报告

> 审计对象：`VC_Go/docs/1.0 生产与市场模拟.md`（612 行，最终版）及其 Go 内核实现 `VC_Go/gosim/`
> 审计方式：编译 + vet + 单元测试 + 10,000 周期实跑 + 自建货币守恒审计测试
> 审计日期：本次会话
> 一句话结论：**未通过验收。** 实现可编译、可运行、契约标定层全部兑现，但主模拟在 ~3,000 周期内全经济归零，"通过 3/6" 的三条判据是在系统死亡后的空真通过。

## 三、阻断项一：货币不守恒

### 3.1 契约要求

§4.5.3 明确声称：

> "税收 → 政府 → 建造部门（工资 + 投入）→ 回到居民/企业流通"与"企业现金池 → 政府（购买建造力）"两条流方向相反、金额相等，因此**总流通货币不变**。

### 3.2 实测

审计01（`TestAudit01MoneyConservation`）：

```
初值 总货币 = 5,075,000
tick 1   总货币 =  3,361,523   Δ = −1,713,477  (−33.76%)
tick 2   总货币 =  1,678,809   Δ = −3,396,191  (−66.92%)
tick 3   总货币 =     59,885   Δ = −5,015,115  (−98.82%)
tick 4   总货币 = −1,415,255   Δ = −6,490,255  (−127.89%)
tick 5   总货币 = −2,732,382   Δ = −7,807,382  (−153.84%)
```

**总货币变为负数。** 货币存量在 5 个周期内被彻底摧毁。系统无造币/销毁机制，任何偏离 0 的 Δ 都是记账漏出。

### 3.3 两个方向相反的独立漏出点

审计03（`TestAudit03WageNeverPaid`）通过"把每级劳动人数置零"隔离工资流：

```
含工资成本  5 tick Δ货币 = −7,807,382（销毁）
工资置零    5 tick Δ货币 = +4,551,227（创造）
```

符号反转，证明存在**两个独立**的违背：

#### 漏出点 A：工资从未被支付（销毁）

- 契约 §5：工资是居民**唯一**资金来源，"全部工资用于消费"。
- 实现：`step.go` 里工资只作为成本从利润中扣减（`LastProfit = 收入 − 投入 − 工资`），**没有任何账户收到这笔钱**。
- 没有 wagePool，没有家庭账户。消费结算的预算参数 `totalWage` 是凭空算出的数，不对应任何余额。
- 后果：工资算出 1,712,219，实际消费支出只有 486,255（**工资回收率 28.40%**），其余全部蒸发。

> 这正是 `FEASIBILITY-1.0.md` §5.2 列为"尚未核验"的那一条——**"§8 主循环中工资的去向（工资计入利润却不进消费池，货币不守恒）"**。该问题当时未被验证，现在被确证，且它是整局坍缩的第一驱动。

#### 漏出点 B：对中间投入计征的税无处扣缴（创造）

- `fiscal.CollectTax` 的税基是"消费者最终购买额 + **中间投入交易额** + 建造力交易额"。
- 消费者侧在 `consume.Purchase` 用 `affordable = budget/(1+taxRate)` 扣了税；
- 建筑侧只在收入上除了 `(1+taxRate)`（`LastRevenue = saleValue/(1+t)`）；
- **中间投入环节没有任何账户被扣税。** 政府却把这笔税全额入账。
- 实测隐含税率 `税收/消费支出 = 0.176`，而正确值应为 `t/(1+t) = 0.0909` —— 差额正是无处扣缴的中间投入税。

## 四、阻断项二：利润分账重复入账

`VC_Go/gosim/internal/sim/step.go` 对同一笔利润做了两次入账：

```go
// ⑤ 收入结算与利润分账
govOperating += b.LastProfit * share          // 政府份额
capitalIncome += b.LastProfit * (1 - share)  // 私有份额
b.Cash.Add(b.LastProfit)                     // ← 建筑池拿【全额】利润

// ⑥b 先把全部收入入账
s.Gov.Cash.Add(govOperating + s.Gov.TaxCollected)   // ← 政府【另外】再拿一份
```

`step.go` 第 106–114 行有一段注释，记录了历史上"政府经营净额被记了两次"的 bug，并说明"分配与入账必须分开，只做一次"。**修掉的是政府侧的那一次，建筑侧那一行 `b.Cash.Add(b.LastProfit)` 没有同步改成按份额入账。**

审计02（`TestAudit02ProfitDoubleCredit`）给出特征值：

```
tick 1  Δ货币 = −1,713,477   Σ利润 = −847,848   Δ/Σ利润 = 2.021
tick 2  Δ货币 = −1,682,714   Σ利润 = −830,197   Δ/Σ利润 = 2.027
tick 3  Δ货币 = −1,618,924   Σ利润 = −794,889   Δ/Σ利润 = 2.037
tick 4  Δ货币 = −1,475,140   Σ利润 = −743,236   Δ/Σ利润 = 1.985
tick 5  Δ货币 = −1,317,127   Σ利润 = −664,713   Δ/Σ利润 = 1.981
tick 6  Δ货币 = −1,124,270   Σ利润 = −566,970   Δ/Σ利润 = 1.983
```

比值稳定在 **2.00**。若三方是"划分"关系，比值应为 1；实测等于 2，即单笔利润产生双倍记账。本例中利润为负，故表现为双倍销毁；利润为正时即为凭空造币。

注：**这部分是工程问题，契约无责。** 契约 §4.5.1 写的是"运营纯利**按持股比例分配**"，实现把"分配"做成了"复制"。

### §8.4 判据判定

```
A1 未通过   贴边率 100%，max|ln(P/Pcost)| = 1.6094（= ln5）
```

### "通过 3/6" 是空真通过

审计04（`TestAudit04VacuousAcceptance`）证明这三条判据无法区分"有界稳定"与"系统死亡"：

- **A2** 要 `margin ∈ [−10%, +25%]`。经济死亡后全部 margin = 0，落在区间内 → 通过。契约自认的"封闭经济全局利润恒为 0 ⇒ 11 部门必然分组"这一矛盾，在死亡态里被"解决"了——因为已经没有部门了。
- **A3** 要均衡点不漂移。经济死亡后 `Δ(P/Pcost) = Δ(S/a) = 0` → 通过。零漂移是因为什么都不再发生。
- **A6** 要"队列非空 tick 占比 < 20%"。经济死亡后成交占比 0% → 通过。契约原意是"建造力供给跟得上"，空队列在这里被读成了好消息。

**因此，"通过 3/6" 不构成任何正面证据。** 实际含义是"6 条判据无法识别整局坍缩"。

## 六、根因结构

坍缩链条（每一环都有实测支持）：

```
① 工资从未真正支付 ──→ 每 tick 销毁 ~1.2e6 货币（审计03）
② 中间投入税无处扣缴 ─→ 每 tick 创造 ~1.7e6 货币（审计03 反向）
③ 利润双重入账 ──────→ 单笔利润 2 倍影响（审计02）
        ↓
货币存量被摧毁，5 tick 后为负（审计01）
        ↓
消费支出塌到工资的 28%（工资回收率 28.40%）
        ↓
必需品满足度跌破 75%（tick1 简朴衣物/基础食物 = 1.000，但住宅仅 0.136）
        ↓
§6.5 人口增长率转负，年化 −20% 上限
        ↓
人口 → 0，雇佣率 → 0，§4.4 缩编把全部建筑清零
        ↓
价格锁死在钳制上限，市场死亡 → A2/A3/A6 空真通过
```

**一个前置问题**：开局的 20% 利润率是账面假象。契约 §3.4 用"工资 + 中间投入"算出 20% 利润率，但那 20% 从未对应过真实购买力——工资总额 17.1e6/tick，而全社会货币存量只有 5.1e6，消费只能实际发生 0.49e6。**利润率是标定出来的，不是赚出来的。**

## 七、契约自身的缺陷（需修订，非实现问题）

这些是文档级缺陷，与实现无关，**必须在 1.0 定稿前修订**：

1. **§8.4 判据 A1 恒为未通过**：阈值 `ln5` 与钳制上限 `5·P_cost` 完全重合，价格触边时 `|ln(P/P_cost)|` 恰等于 `ln5`，而"贴边占比 < 5%"本身就在禁止触边。判据对自己定义的行为恒判失败。（契约 §8.4 已自认）
2. **§8.4 判据 A2 不可达**：封闭经济中居民收入 = 工资、消费者支出 ≤ 工资，故全局总利润恒为 0；11 个部门必然分为盈利组与亏损组，`[−10%, +25%]` 无法覆盖。（契约 §4.1、§8.4 已自认）
3. **§8.4 判据 A3 与 §6.5 互斥**：人口年增 5% 时 `S/a` 每周期漂移约 `9.4e-4`，超出 `2e-4` 限值一个数量级。A3 只在人口停止增长时成立，而那不是契约要的活稳态。（契约 §8.4 已自认）
4. **§4.2 自给农场规模口径缺失**：契约只写"未利用耕地自动生成自给农场"，**未给每单位耕地对应几个自给农场**。由于耕地上限 10,000 级而需求只用到约 5 级，99.95% 的耕地都算未利用；该系数直接决定谷物价格是否被永久压在地板价。契约自认这是"未定项，影响极大"，实现取 0.05（建模选择，非契约值）。
5. **§4.3 建造力付款方缺失**：契约只写"建造力费用从现金池扣除"，未定义收款方。缺口 `5.1e4` 倍已由 `VC_Go/tools/construction_sink_probe.js` 量化。§4.5 的 G1/G2/G6 是对它的补全，但**补全引入的记账规则（谁在何时扣税、利润如何划分）契约未写**，这正是第三节两个漏出点的来源。
6. **§8 主循环缺工资入账步骤**：15 步里没有任何一步把工资记入居民账户。§4.5.3 声称的"回到居民/企业流通"在循环中没有对应步骤。

## 八、回答"能否作为市场模拟游戏的核心逻辑"

**当前状态：不能。** 理由分三层，第 1 层是阻断性的，第 2、3 层是设计选择。

### 第 1 层：模拟在 3,000 周期内死亡（阻断）

一个市场模拟游戏的核心循环必须能无限期持续运行。当前内核在 3,000 周期内把人口、产能、交易全部归零，且归零后进入一个"所有指标都稳定"的假稳态——从外部看像是收敛，实际是死亡。**在这个问题解决前，任何玩法层设计都没有承载物。**

### 第 2 层：契约明确把玩家排除在 1.0 之外（设计选择）

`ARCHITECTURE.md` §1.3 把"玩家 UI 交互与存档读档"列为 **1.0 非目标**（归 1.1）。契约 §4.1 的"简易 AI 实现利润驱动的自动扩建"是唯一的行为主体。所以 1.0 的定位是**内核标定 + 收敛性验证**，本就不是游戏。

### 第 3 层：三个"游戏杀手"设计

即使内核跑通，以下三点也会直接摧毁可玩性：

1. **"所有商品 20% 利润率"与市场游戏互斥。**
   市场游戏的全部张力来自**部门间利润率差异**——玩家要判断"该投哪个行业"。契约 §3.4 把 11 个部门的开局利润率统一标定为 20%，等于取消了选择。更根本的是，这个统一值在封闭经济里数学上不可能维持（全局利润恒为 0）。实测 tick 1 的利润率分布已经暴露这一点：谷物 +15%、织物 +31%、建造力 +151%，而加工食品 −56%、高档服装 −100%、铁 −80%、钢 −72%。

2. **模型没有玩家可操作的对象。**
   契约 §4.1 把扩建决策交给 AI（margin > 10% 自动扩建），§4.5.1 把所有权固定为政府 70%，§4.3 让"资金不足时停工"自动发生。玩家没有可下的决策：价格由 ODE 自治，产能由 AI 自治，资金由税收/债务规则自治。要变成游戏，必须把人放回决策环——但这需要重新设计，不是调参。

3. **所有价格撞在钳制带上，价格信号失效。**
   `P_floor = 0.2·P_cost`、`P_ceil = 5·P_cost` 的窄带内，`ε` 的差异被压平。末态 11 种商品有 9 种锁在 5.000，价格不再是信息。契约自认 A1 因此恒判失败。

### 若要成为游戏内核，需要的最小改造集

按优先级：

| # | 改造 | 位置 | 说明 |
|---|------|------|------|
| 1 | 建立工资→家庭的真实记账 | 契约 §5 + §8 | 新增 wagePool，工资在同一 tick 记入并支出。这是货币守恒的前提，也是让"居民"成为可被政策影响的对象 |
| 2 | 统一税率在各环节的扣缴口径 | 契约 §4.5.3 | 中间投入税必须真从某个账户扣除，否则税基定义就是造币机 |
| 3 | 利润分账改为划分而非复制 | `sim/step.go` | `b.Cash.Add(profit*share)` 而非 `Add(profit)` |
| 4 | 引入外部部门，打破"全局利润恒为 0" | 契约 §3.3 | 封闭经济里不可能所有部门同赚。要么加政府最终购买/出口，要么承认部门分化并据此设计玩法 |
| 5 | 给玩家真实决策权 | 契约 §4.1 / §4.5.1 | 至少让"投哪个行业、扩多快、是否举债"成为玩家选择而非 AI 规则 |
| 6 | 修订 A1/A2/A3，加上"存活判据" | 契约 §8.4 | 现有 6 条判据无法识别坍缩，必须新增"人口与产能不为 0""货币存量守恒"这类硬判据 |

### 可以作为游戏内核的部分（应当保留）

- **§2 价格动力学**：常弹性需求 + `m·P'' + ρ·P' = E + F_ext` 的二阶系统，用 `T`、`ζ` 作全局旋钮反推 `m`、`ρ`。局部刚度 `K(P)`、尺度不变性（`γ = 0`）、RK4 自适应子步、特征根实部定收敛时间——这套设计是干净的，`internal/market` 的单元测试全绿。**这是整个项目最有价值的资产。**

#### 10.1.1 本轮修复的逐建筑对账缺陷（"全局全绿"掩盖"明细口径分叉"的实例）

逐建筑对账实测残差 **2,134,022**，而同一时刻 §4.5.3 的货币守恒、
借贷相等、政府现金流分解三项**全部通过**。原因是三处独立的缺陷：

| # | 缺陷 | 性质 |
|---|------|------|
| 1 | `BuildingRecon.ConsumerIn` / `InputIn` 两个字段**从未被填充**——`distributeConsumerRevenue` 是死代码（从未被调用），`InputIn` 根本没有赋值处 | 明细缺失 |
| 2 | `InputOut` 记的是**理论申报额** `InputValue`（税前），而记账簿实际借记的是**含税实付额**（且买方现金不足时会缩减） | 口径错位 |
| 3 | 利润划分被当成"留存份额"，而 `book.ProfitSplit` 的记账腿是**「借 建筑 全额利润、贷 建筑 留存份额」**，现金池的净腿是 `留存 − 利润`。利润为负时符号相反，误差达 `2×\|利润\|` 量级 | 口径错位 |

其中缺陷 3 是残差的主项，且它有一个很隐蔽的后果：
`ExpectedDelta()` 用错口径后，残差恰好在数值上"看起来像"其它项
（实测残差 2,134,022 与消费收入 793,637、政府经营 −1,098,204 都不相等，
无法用肉眼归因），**必须靠留一法逐项试算才能定位**。

**修复**：
- `book.Consume` / `book.PayIntermediate` 改为返回它们**实际贷记的逐卖方金额**与
  **实际借记的逐买方金额**，sim 只登记这份"记账事实"，不再自行重算分摊
  （重算是缺陷 2 的根源，也是"两处口径分叉"的温床）；
- 新增 `BuildingRecon.ProfitLeg` 与 `Recon.ProfitLegTotal` 记录利润划分的净腿；
  `RetainedProfit` 降为管理口径的报表字段；
- 删除死代码 `distributeConsumerRevenue`——它若被误接回去会**重复贷记**消费者货款，
  直接破坏货币守恒，故连同它的重算逻辑一并删除；
- `TestAuditBuildingRecon` 原先**只打印、不断言**（注释却声称"必须被完全解释"），
  现补上汇总与逐建筑两级残差断言。

修复后：汇总残差 `0.00`，逐建筑残差全部 `0.00`。

> **教训**：全局不变量（货币守恒、借贷相等）能证明"钱没丢也没多"，但**不能证明
> "每一笔都归对了户"**。前者是全账户求和后的标量，后者是逐账户的向量；标量相等
> 完全可以由"一处多记、另一处少记"凑出来。因此逐账户对账必须有自己的断言，
> 且它的口径必须直接取自记账处，不能在诊断侧重算。

### 10.3 但平衡态不可达：三条结构性障碍

**障碍一：全过程 10% 交易税与"按 t=0 标定"的需求缩放系数不自洽。**

`calibrate.jointDemandScale` 的注释写定"这里不含税率，故基准情形按 t = 0 标定"，
于是 `k` 满足"工资 = 最终需求价值"**只在不收税时**成立。实收 10% 后：

```
平衡等级合计 L*             =     688.61 级
工资总额                     = 23,240,505.95
最终需求价值（P_cost 计价）  = 23,238,815.60
不收税覆盖率 = 工资/需求     =      1.000073     ← 恒等式，非巧合
10% 税后可购价值             = 21,127,732.69
10% 税后覆盖率               =      0.909157     ← 结构性缺口 9.0843%
```

即：**居民在手现金买不下 §6.3 表列的名义需求**，缺 9.08%。
这不是实现缺陷，是"需求表按税前标定、税制按全过程征收"两条契约条文的直接冲突。

**障碍二：起点产能远低于平衡产能，导致大范围负利润率。**

统一 5 级布点合计 70 级生产建筑，平衡需 688.61 级，**差 9.8 倍**。实测起点
（`TestAuditStartDiag`，人口 10m）：

```
名义需求（P_init 计价）/ 税后购买力 = 13.4860
名义需求（P_cost 计价）/ 净供给     =  7.5943
净供给（P_cost 计价）  / 税后购买力 =  1.3700     ← 供给比购买力还小
煤/铁/钢/工具的净供给 = 0（被上游互相吃光），铁配给比 0.375
```

故 t = 1 就有 8/11 个部门利润率为负，`margin > 10%` 的扩建条件永不触发，
只能靠 §4.4 缩编单向收缩。

**障碍三：政府是 70% 所有者，交易税养不起它的工资。这是主因，且与起点、税率都无关。**

清分账（`TestAuditGovDecomp` 残差恒为 0）：

```
Δ政府 = (税收 − 自收自支税) + 政府经营净额 − 采购支出 − 自建付款
tick 1：−1,228,500 = 104,435 + (−1,098,204) − 213,392 − 21,339     残差 0.00
```

政府经营净额 ≈ −（政府工资）+（70% × 全经济利润）。而**资本收入在全部商品价格
等于零利润价时恰为 0**，故政府经营的实质就是"政府替它持有的 70% 产能垫付工资"。
于是政府资金缺口有闭式表达：

```
政府需要  = 0.70 W        （W = 工资总额；政府持有约 70% 产能）
政府收入  = 0.095 W       （10% 全过程交易税，按统一 5 级实测税率反算；
                           平衡口径更低，净交易税 ≈ 0.037 W）
缺口      ≈ 0.61 W        ← 与需求缩放 k、与起点布点都无关
```

10m 人口下这是每 tick **约 1,100 万～2,100 万**的刚性缺口。
而 G7 的债务上限只有 `2.739116 × 建造力产出 × 建造力价格`
（统一 5 级时上限 274 万，物质平衡布点时为 4,150 万），
即"约 3～6 个周期的资金"——**必然在数百周期内触顶，G2 一停摆就进入死亡螺旋**。

### 10.4 对照实验：换布点、换税率都不改变结局

`TestAuditSurvival`（人口 10m，600 周期，四组对照）：

| 布点 | 税率 | 起始级数 | 100 周期工资 | 末态级数 | 存活 |
|------|-----:|--------:|------------:|--------:|-----|
| 统一 5 级 | 0.10 | 84.0 | 2,273,318 | 10.1（12.0%） | ✗ |
| 统一 5 级 | **0.00** | 84.0 | 2,269,408 | 10.0（11.9%） | ✗ |
| 物质平衡 | 0.10 | 1,435.6 | 38,168,909 | 146.7（10.2%） | ✗ |
| 物质平衡 | **0.00** | 1,435.6 | 38,175,577 | 146.7（10.2%） | ✗ |

- **税率几乎不影响**：成交额被供给约束卡住（`最低满足度`在 100～400 周期恒为 1.000，

### 10.5 由此得到的契约裁决建议

1. **政府持股比例与交易税必须二选一或匹配**。当前"70% 持股 + 10% 交易税"在
   任何起点、任何需求标定下都不自洽：政府必须为 70% 的产能垫付工资，却只收到
   约 9.5% 的税。可行档位：
   - 保持 10% 交易税 → 政府持股必须降到 **约 4%** 以内；
   - 保持 70% 持股 → 需要有覆盖 **约 70% 产出价值** 的收入来源（不是交易税）；
   - 或把"政府持股"明确为**只分红不担亏**，并把工资义务移出政府。
2. **债务上限的资产基数只取建造力产出**（`AssetBase = PowerOutput × P_power`），
   仅够 3～6 个周期的资金，与政府承担的工资义务规模不匹配。要么把资产基数扩到
   政府持有的全部资产，要么显式接受"政府会周期性停摆"作为玩法机制。
3. **需求缩放系数 `k` 的标定必须带税率**，否则 §6.3 需求表在 t > 0 就系统性
   高于居民可支付额 9.08%。
4. **起点产能与平衡产能的量级差（9.8 倍）需要显式设计**：若希望"从短缺起步、
   靠市场补齐"，必须保证起点利润率足以触发 §4.1 的扩建阈值——当前统一 5 级
   布点做不到（8/11 部门开局即负）。
