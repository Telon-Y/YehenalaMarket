## 0.2d 第 14 / 15 项：参照结论 → Go 条款（2026-09-20）

### 第 14 项：国家市场的形态

**参照结论**：国家市场层**只是一个成员边界框架 + 只读聚合**，**不应有可写状态**。
依据是三条规范原文级的表述：

| 参照结论 | 落成 Go 条款 |
|---|---|
| 国家市场 = "其本地市场的**成员边界**"；"聚合与国内贸易政策**将在此基础上追加**" | 1.1 的 `Nation` **只承载**：标识、所属、成员市场列表、成员判定。**不新增可写业务状态** |
| 国家层聚合"**由成员快照计算而来，而不是另存一份可写的人口/GDP 总量**" | 1.1 的聚合视图**按需计算、绝不缓存**、**绝不回写** `State`；即 §0.2-4 的"无状态"在此得到参照确认 |
| "GDP 与人口与成员快照使用**同一周期规则**；若各省周期不同，国家快照报告**成员中的最小周期**，以免把混合数据标成同一期" | **单期约束**：仅当全部成员市场处于**同一 tick** 时才聚合；若不同，则整个视图标注为**最小 tick**，并在界面显式提示"混合期" |

> **1.1 的落地范围**：`maxMarketCount = 1`，故国家视图的读数**与单市场相同**（这是第 14 项 (b) 的含义）。
> 落地点是 §0.2b-13 决定的 `report` 包；**`report` 不得写账、不得参与 tick 管线**。

### 第 15 项："其他"页的栏目

**参照结论**：对应的面板标题为"**宏观与物流**"，其结构是
**① 4 张指标卡 + ② 一张 7 列的市场对照表 + ③ 物流两栏列表**。

**① 指标卡（4 张）** → 1.1 采用：

| 卡片 | 1.1 取数（Go 侧字段） |
|---|---|
| 年化 GDP | `SpendNet + CashTotal`，按 52 周折算 |

| 中间投入 | `ProductInput` |

**② 市场对照表** → 1.1 由 7 列扩为 **8 列**（按 §0.2-4 的聚合口径，明确要求**数量加权均价**）：

| 列 | 说明 |
|---|---|

## 0.3 对 1.0 的实质影响（登记）

> §0.2 的裁决不是纯 UI 改动：下列两项**改动了 1.0 的数值路径或判据口径**，须单独登记。

1. **A8 必须开显式例外（拆除核销所致）**。契约 §8.4 :1854 现为
   `|ΔM − (NewCapital + 诊断注入)| ≤ max(1e-3, 1e-8×货币存量)`；
   拆除会**销毁货币**，故须改为 `ΔM == NewCapital + Infusion − Δ(累计核销)`，
   并保留"**未申报的货币减少仍然违规**"这一更强的形式（详见 §六-1）。
   **收益**：1.0 的 A8 是"构造性恒真"（两侧同源 `TotalMoney`，判别力 ≈ 0）；
   加上申报口径后它能区分"**申报核销**"与"**漏记一条腿**" ⇒ **判别力比 1.0 更强**
   （该结论的实测依据见 `out/review/REVIEW-FINAL.md` §3）。
2. **§4.4 建筑自动缩编保持冻结**（`DecayFrozen=true`），拆除由**玩家手动**触发。
   两者互补；**不得**为了拆除而把 `DecayFrozen` 翻回 `false`（那会同时改变 AI 侧行为）。
   唯一例外：在**对照审计**中显式注入 `DecayFrozen=false`（沿用 `audit_tasks_test.go:259` 的写法）。

## 三、玩家动作

> 每个动作一行：**前置条件 / 记账腿 / 收敛性 / 生效时机**。
> **记账腿一栏必须逐条写死**——这是"玩家 = 政府"能保住 A8 的关键。

| # | 动作 | 前置条件 | 记账腿 | 生效时机 |
|---|------|----------|--------|----------|
| 1 | **建造**（x1/x5/x10） | 显式建筑；不超上限（完工时裁剪）；不绕过 `AvailableCash` | 复用既有 G2 路径：`book.PurchasePower` + 完工归属 | 立即 |
| 2 | **置顶** | 该订单存在且未被置顶 | 无（仅改顺序） | 立即 |
| 3 | **拆除** | 显式建筑（`Produces() && !IsNonMarket() && !IsAgent`）；仅**政府级** | **新增** `book.DemolishBurn`：借 建筑池余额 / 贷 销毁账户；在途订单取消不退款 | 立即 |
| 4 | **调速 / 暂停** | — | 无（不改状态） | 立即 |
| 5 | **调参** | 参数在 §0.2-11 与 §0.2-9 的白名单内 | 无 | 立即 |
| 6 | **查看** | — | 无（只读） | — |

> **§三-1 与 §三-2 的关系**：玩家建造**不绕过现金约束**，仍受 `AvailableCash` 限制（`fiscal.go:230`）；
> "置顶"只改**队列顺序**（优先级：玩家 > §4.2 预警插队 > FIFO）。
> **§三-3 的核销**：建筑池允许透支（`step.go:1496`），故余额可能为负；
> **负余额核销 = 销毁一笔负债 = 货币总量增加**。建议统一称"**核销**"并采用**带符号额**（§0.2-16）。

### 4.1 市场页

## 五、时间与确定性

- 渲染 **60 FPS**；逻辑按 **"每秒推进 tick 数"** 驱动（§0.2-11 / §0.2-12）；
- **帧与 tick 解耦**：同一参数下，**tick 序列必须与帧率、倍速无关**。
  这不是洁癖——本项目刚在 `ledger.sortedAccounts()` 修好"同二进制逐位一致"，
  若让帧直接驱动 tick 就会重新打破该保证（`ledger.go:381-394`）。
- 实现建议：逻辑侧维护**累计时间**（或帧计数）来决定本帧是否 `Step()`，**不把倍速写进引擎参数**。

## 六、验收判据

1.0 有 A1–A9；**1.1 目前一条都没有**。至少需要三类：

1. **回归**（最高优先级）：关闭 UI 后 `-ticks 1000` 的五个锚点值逐位不变 ——
   人口 **5745609** / 政府 **−67827546** / 资本 **−2771479061** / 投资池 **3033986118** / 税收 **310855**
   （此五项已由本轮独立复跑验证为 1.0 现状）。
2. **动作生效**：每个玩家动作有可观测效果。**必须带防空真守卫**——参照现有写法
   （如 `state_test.go:161`、`audit_r26_test.go:280` 的"若 N tick 内未发生 X ⇒ 断言被空真通过"）。
3. **不变量**：玩家动作全程 `借贷违规 = 0`、逐建筑对账残差 = 0；
   **A8 需按 §三-3 改写为带申报口径的 A8′**（见下）。

### 6.1 A8′（拆除核销之后）

契约 §8.4 :1854 现为：

```
|ΔM − (NewCapital + 诊断注入)| ≤ max(1e-3, 1e-8 × 货币存量)
```

1.1 起必须改为：

```
ΔM == NewCapital + Infusion − Δ(累计核销)
并且：未申报的货币减少（残差 < 0 且不属于申报核销）仍然判为违规
```

> **这一条同时是收益**：1.0 的 A8 是"构造性恒真"（两侧同源 `TotalMoney`，判别力≈0）；
> 加上申报口径后，它能区分"**申报核销**"与"**漏记一条腿**"，**判别力比 1.0 更强**。

## 七、与 1.0 / 2.0 的关系

- **不推翻 1.0**：冲突时以 1.0 为准；
- **2.0 的门槛**（1.1 只需不阻断）：
  1. 进程内并存**多个 `State` 实例**（已核实：`sim` 无可变包级状态，`BuildingSpecs()`/`DefaultParams()` 每次返回新值）；
  2. `Params` 按**作用域拆分**（市场级：`ArableCap`/`TaxRate`/`GovInitialShare`/… ；
     国家或全局级：`TicksPerYear`/`HireAnnual`/数值约定）；
  3. `Nation` 聚合视图从 1 个市场扩到 N 个（§0.2-13 / §0.2-14）；
- **本版明确不做**：多本地市场、库存、地块、国家市场实现、跨市场贸易、关税、货币政策。
