# 1.1 前端设计（契约的下游产物）

> **性质**：本文件是 `docs/1.1 图形化界面.md`（**1.1 契约 v1.0**）的**设计规格**，
> 不是契约本身。**与契约冲突时以契约为准**；本文件只负责把契约的条款落成可实现的界面决策。
> **约束（全部来自契约，不得违反）**：
> ① 技术栈 = **HTML，自包含**（无 CDN、无 npm、无网络请求、无构建步骤）；
> ② 字体 = 根目录 `MingChinese.ttf`，字号 **20**（经 `@font-face` 加载）；
> ③ 渲染 **60 FPS**，逻辑**默认 1 tick/s**、档位 ×0/×1/×2/×5，`N = 60 ÷ (tick/秒)`；
> ④ 四个一级菜单：**市场 / 建筑 / 建筑队列 / 其他**；
> ⑤ 队列页**每页 20 条**；拆除核销**带符号额**；玩家动作**立即生效**。

---

## 一、设计目标与三条原则

**目标**：兼顾**好看**（一眼看出系统在往哪走）与**实用**（每个格子都能追到唯一字段）。

| # | 原则 | 为什么（来自本项目的实测教训） |
|---|------|------------------------------|
| P1 | **同一屏内必须有"名义 vs 实际"对照** | 1.0 长跑实测：价格指数 ×9.9e4、名义货币 3.2e7、名义 GDP 2.6e13，而居民实际货币余额从 6.7e6 掉到 319。**只看名义会把恶性通胀读成高速增长** |
| P2 | **状态色必须区分"健康/告警/越界"，且不能只靠颜色** | A2 的 ±450% 上限恒真、A6 靠增长豁免短路——**判据本身会撒谎，界面必须把原始量摆在前面**（贴边率、亏损占比、债务÷上限、实际增加值斜率） |
| P3 | **不做假数据、不做占位图表** | 契约 §0.2d 已载明"不得显示仓库纯利"（份额按设计固定为 0）。空数据要**显式写"无数据"**，不能用平线假装 |

## 二、设计令牌（Design Tokens）

### 2.1 颜色 —— 与项目现有渲染器**同一套**，仅扩展数据色

现有 `tools/md2html.js` 已定义：`--ink:#1f2328` / `--ink-2:#57606a` / `--line:#d8dee4` /
`--bg:#fff` / `--accent:#0969da` / `--panel:#f6f8fa`。**新前端沿用这六个**，保证"文档与界面是同一个产品"。

扩展的**数据色**（仅用于图表，不用于文字正文）：

| 令牌 | 亮色 | 用途 |
|------|------|------|
| `--up` | `#1a7f37` | 增长/正利润（与 `--accent` 区分，避免"链接色=数据色"） |
| `--down` | `#cf222e` | 收缩/负利润/越界 |
| `--warn` | `#9a6700` | 接近阈值（如债务÷上限 ∈ [0.8, 1.0)） |
| `--neutral` | `#8250df` | 中性基准线（如 `P/P⁰ = 1`、指数基期 = 1） |
| `--grid` | `#eaeef2` | 网格线 |

**图表分类色（14 商品固定顺序，不随排序变化）**：使用一组**色相分散且明度接近**的 8 色循环，
**同一商品在所有图表中恒为同一色**——这是 P0 要求，否则跨图对照会失效。

### 2.2 排版

| 项 | 值 | 依据 |
|---|---|---|
| 正文字体 | `@font-face` 加载 `MingChinese.ttf` → 回退 `"Segoe UI","Microsoft YaHei",sans-serif` | 契约 §0.2-2 |
| 正文/表格字号 | **20px**（契约指定）；**紧凑表格可降至 16px**并标注为"网格用小号" | 契约要求 20；但 14 商品 × 8 列的表在 1080p 下必须允许小号 |
| 等宽数字 | `font-variant-numeric: tabular-nums` | 数值列必须能上下对齐，否则 60 FPS 下会抖动 |
| 字重 | 400 正文 / 600 标题 | — |

> ⚠ **字体体积**：`MingChinese.ttf` **24.4 MB**，全量 CJK。首次加载会有可感延迟。
> 处理方式（二选一，**不违反"自包含"**）：① 直接加载并在页面上显示加载进度；
> ② 用字体子集化工具裁到本项目用得到的字符集（界面文案 + 商品名 + 建筑名，估计 < 200 KB）。
> **建议②**，但**子集化后的文件必须一并入库**，否则不满足"自包含"。

### 2.3 间距与圆角

`--gap: 12px` · `--gap-lg: 20px` · `--radius: 8px`（与渲染器的 8px 圆角一致）。
**情报密度优先**：本界面是仪表盘而非营销页，区块间距取 12/20 两档，不做大留白。

## 三、布局

### 3.1 应用骨架（固定，不滚动整页）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：市场名 │ tick │ 速度 ×0 ×1 ×2 ×5 │ ⏸/▶ │ 货币存量 │ 告警灯 │  ← 48px 固定
├────────────┬─────────────────────────────────────────────────┤
│            │                                                  │
│ 一级菜单   │   内容区（各页自己滚，整页不滚）                  │
│ 市场       │                                                  │
│ 建筑       │                                                  │
│ 建筑队列   │                                                  │
│ 其他       │                                                  │
│            │                                                  │
│ ← 200px    │   ← 自适应                                     │
├────────────┴─────────────────────────────────────────────────┤
│ 状态栏：借贷违规 │ 逐建筑对账残差 │ 核销累计 │ 判据 A1–A9 摘要   │  ← 32px 固定
└──────────────────────────────────────────────────────────────┘
```

**为什么顶栏与状态栏固定**：判据与记账不变量是**每 tick 都在变**的观测量（A8 残差、借贷违规、核销累计），
藏进子页面就会变成"出问题才去看"。它们必须**常驻可见**。

### 3.2 响应式

| 宽度 | 变化 |
|---|---|
| ≥ 1600px | 市场页：左侧商品二级菜单 + 右侧详情，底部总图通栏 |
| 1200–1600px | 同上，图表高度由 260 降为 220 |
| < 1200px | 一级菜单收为**顶部横向标签**；详情与总图**上下堆叠** |
| < 900px | 表格改为**卡片流**；不追求移动端完整功能 |

## 四、组件规格

### 4.1 指标卡（Metric Card）

用于"其他"页的 4 张卡与顶栏。结构：**标签（--ink-2, 16px） / 数值（20px, tabular-nums, 按状态着色） /
副行（环比或占基期比例）**。

- **负值必须着色 + 加方向符号**（`▼`），不能只靠颜色（P2）；
- 数值超长时**缩位**（万/亿/万亿），**但悬停显示精确值**。

### 4.2 数据表

- 表头**吸顶**；数值列**右对齐**；状态列用**色块 + 文字**双重编码；
- **排序**：点表头切换升/降；**排序列不改变分类色**（§2.1）；
- **行内迷你条**（bar-in-cell）：用于贴边率、亏损占比这类 [0,1] 量，**长度即数值**，比数字更快读出。

### 4.3 图表（三类，够用即可）

| 类型 | 用在哪 | 规格 |
|---|---|---|
| **多序列折线** | 价格史、GDP 史、人口、幸福度、货币存量 | 最多 8 条；**图例可点选隐藏**（契约 §4.1 要求）；基准线（`=1`、`=0`）用 `--neutral` 虚线 |
| **堆叠面积** | 实际增加值分部门（农业/工业/自给农场） | 用于看"结构变化"，比三条独立折线清楚 |
| **饼图** | 阶级比例、阶级现金池 | **仅 2 个**（契约 §四-4 冻结）；> 6 片时改用横向条形 |

**坐标轴规则**：价格类**用对数轴**（1.0 实测价格跨 6 个数量级，线性轴会把早期全压成 0）；
金额类**用线性轴但标注缩位单位**；时间轴固定按 tick，**不按帧**（契约 §五）。

## 五、四个页面的落地

### 5.1 市场页（契约 §4.1）

左：商品二级菜单（14 项 + **图例开关勾选框**）。右：详情 = 名字 / 现价 / **两个相对价分行**
（`P/P⁰` 与 `P/Pinit`——契约 §二 明确要求分开命名，不可混为一谈）/ 生产量 / 消费量。
下：**近期图**（末 60 tick）与**全期图**（全程）。
最底：**全商品总价格图**（通栏，各商品固定色，经二级菜单可取消显示）。

**必须加的一格**：详情里要并列 **工资总额 / 消费支出 / 结余入池**。
原因：1.0 已删除"全部工资用于消费"，且 σ_save 默认 1 —— 只看"消费量"会把**储蓄渠道**误读成"没人买东西"。

### 5.2 建筑页（契约 §4.2）

全部生产建筑（含自给农场）+ 逐行：名字 / 数量（**含扩建中**）/ 雇佣率 / 现金池 / 利润率，
右侧 x1/x5/x10 的**建造**与**拆除**按钮。

- **原材料不足红字**：判据 = `produce` 的配给比 < 1（契约 §0.5-U2），**不用** `MarginEMA < 0`；
- 现金池**允许为负**（1.0 实测政府池可到 −1.85e12），负值用 `--down` 且**不得显示为 0**；
- 拆除按钮需**二次确认**并显式提示"**资产与货币一并核销、在途订单不退款**"（契约 §0.2-7）。

### 5.3 建筑队列页（契约 §4.3）

每页 **20** 条，左右键翻页，**标注页数**。每条：建筑类型 / **已建部分 ÷ 总建造力**（进度条）/
剩余时间。**置顶**按钮仅对玩家可置顶的条目可用（契约 §0.2-6 的优先级：玩家 > 预警插队 > FIFO）。

### 5.4 其他页（契约 §四-4，**栏目已冻结**）

① **4 张指标卡** → ② **8 列市场对照表** → ③ **历史曲线组**。
（参照侧的"物流两栏"**明确不做**——1.1 无库存/运输，归 2.0。）

- 硬约束：**不得显示仓库纯利**；
- 阶级比例饼图**按固定阶级切**，并在图注注明"与工资表口径的差异"（契约 §四-4）。

## 六、60 FPS 的三条实现义务

1. **永不整表重建 DOM**：数据每 tick 变化，但**节点复用**（keyed update）。14 商品 × 8 列 ≈ 112 格，
   每 tick 全量 `innerHTML` 重建会在 ×5 档（12 帧/周期）掉帧。
2. **图表用一次绘制的 `<canvas>`**，不用 112 个 SVG 节点；仅在数据变化时重绘。
   （契约要求"无网络请求"，`canvas` 是原生能力，不引入依赖。）
3. **帧与 tick 解耦**：渲染循环 `requestAnimationFrame` 恒定 60 FPS；
   **tick 由累计帧数触发**（`N = 60 ÷ (tick/秒)`）。**绝不让帧率或倍速改变 tick 序列**——
   1.0 刚在 `ledger.sortedAccounts()` 修好"同二进制逐位一致"，帧驱动 tick 会重新打破它。

## 七、交互与可达性

| 项 | 规格 |
|---|---|
| 键盘 | `空格` 暂停/继续 · `1/2/5` 切档 · `Tab` 一级菜单 · `←/→` 队列翻页 |
| 悬停 | 所有数据点/色块/表格单元格带 `title` 精确值（沿用渲染器既有做法） |
| 对比度 | 正文与背景 ≥ 4.5:1；`--warn`/`--down` **不单独表示状态**（必带图标或文字） |
| 偏好 | 尊重 `prefers-reduced-motion`：关闭过渡动画 |
| 深色模式 | **1.1 不做**（契约未要求；现有渲染器也未做 `prefers-color-scheme`）。**留待 1.1.x** |

## 八、交付物与文件结构（**无构建步骤**）

```
gosim/cmd/market-ui/          ← 可选：Go 侧起本地 HTTP 只读服务（若需实时）
web/                          ← 纯静态，可直接 file:// 打开
  index.html                  ← 唯一入口，内嵌 CSS/JS 或引同目录文件
  app.css                     ← 设计令牌 + 布局 + 组件
  app.js                      ← 视图绑定 + 渲染循环
  charts.js                   ← canvas 绘图（折线/堆叠/饼）
  fonts/                      ← 字体子集（若取 §2.2 方案②）
  data/                       ← 契约 §二 的只读视图快照（JSON）
```

**约束核对**：无 CDN、无 npm、无网络请求、无构建 —— 双击 `web/index.html` 即可打开。
若需要"实时"，由 Go 侧提供**只读**接口（契约 §0.2-13 已定聚合入 `report` 包），
前端仍不引入任何第三方库。

## 九、验收补充（在契约 §六 之外的界面自检）

1. **可溯源性**：随机抽 10 个界面格子，逐个能追到 `docs/1.1 图形化界面.md` §2.2 的字段锚点；
2. **不撒谎**：无数据处显示"无数据"；仓库纯利**全局搜索不到**；
3. **帧率**：×5 档（12 帧/周期）连续 600 周期，帧间隔 p95 ≤ 20ms；
4. **解耦**：同一参数下**换档位重跑**，tick 序列与 1.0 回归锚点一致（契约 §六-1 的五个值）。

## 十、视觉稿（`web/mockup.html`）与它回报给设计的三个问题

**视觉稿**：`web/mockup.html` —— 自包含单文件（无依赖、无网络请求），假数据但**形状取自真实实测**
（价格指数增长、名义 GDP 起飞 / 实际增加值见顶回落、政府池 −1.85e12、贴边 59.70%）。
双击即开；深链 `#build` / `#queue` / `#other` 直接切页。同目录 `out/review/mockup/*.png` 为四页截图。

**它已经暴露了三个真问题**（在设计阶段就抓到，正是做视觉稿的目的）：

| # | 问题 | 现象 | 结论（已修正/需注意） |
|---|------|------|----------------------|
| V1 | **flex 子项被压缩** | 一级菜单 `<nav>` 在 flex 行里宽度被压缩，`市场` 竖排成"市/场" | 侧栏必须写 `flex:0 0 200px` + `white-space:nowrap`。**这类问题读规格发现不了** |
| V2 | **视口高度耦合** | 容器用 `height:100vh` 时，内容只占视口高度，页面下方留大片空白 | 主区应 `flex:1 1 auto; min-height:0`，`.page.on{min-height:100%}` —— 对任何嵌入/截图视口都正确 |
| V3 | **假数据会自带"台阶"** | 价格序列用硬阈值分段（`i > 0.45N` 起加通胀）⇒ 图上出现不自然的折角 | 假数据也必须用**平滑过渡**（smoothstep）；否则会被误读成模型特征 |

> **V3 尤其值得记住**：视觉稿的假数据如果"看起来像机制"，评审时就会把演示瑕疵当成模型行为。
> 故契约 §四 的"不显示仓库纯利"之外，建议再加一条：**假数据不得制造模型不存在的形态**。
