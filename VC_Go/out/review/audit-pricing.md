## 严重偏差（按严重度排序）

### S1. `P⁰(t)` 的实现比契约公式多乘了一个买家加载系数 w（真实公式分歧）
- **契约**：`P⁰_j(t) = Σ_i A[i][j]·P_i(t) + l_j`（§3.4 L520 与 L533、§2.5 L306、§8 主循环第 2b 步 L1777 三处一致，**均无 w**）。
- **代码**：`gosim/internal/sim/state.go:1641` `pz = s.Params.BuyerWedge()*pz + s.effectiveWagePerLevel(j)/b.Spec.Recipe.Qty`，
  即 `P⁰ = w·ΣA·P + l`，`w = 1.07625`（`model/domain.go:1178-1180`）。
- **后果**：钳制带 `[0.2,5]×P⁰`（`market.go:216-223`）与 A1/A3 的 `P/P⁰`（`market.go:259-261`、`report/report.go:87-88`）整体上移。
  含中间投入的商品在 t=0 抬高 **+5.5%~+5.7%**：建造力 `ΣA·P_init = 5880.49`（`calibrate_test.go` 实跑日志的"w·原料"÷w），
  契约式给 5880.49+2250 = **8130.49**，代码给 1.07625×5880.49+2250 = **8579.6**；炼钢 1076.78+375 = 1451.8 → 1533.9。
  谷物/织物等无投入品者不受影响。
- **性质**：这是"实现悄悄改写契约公式"，而非单纯的文档问题；`internal/sim/audit_r32_test.go:74-81` 反而把 `w·ΣA·P+l` 固化成断言，
  说明它是**有意为之但未回写契约**。契约自身对此也不自洽——同一节的 L467 给 `P_ref` 加了 w、L520 给 `P⁰` 不加 w，两式语义应该同源。

### S2. 三表联合标定系数 k 与契约数字相差 9.3%，且无测试钉住
- **契约**：`docs/1.0 生产与市场模拟.md:201`「默认布点下实测 **k = 1.0400**」；§8.6 L1999 亦"以 k = 1.04…求解"。
- **代码**：实跑 `TestPrintCalibrationTable` ⇒ **k = 0.943161**（`calibrate.go:277-303`）。
- **后果**：k 是 §6.3 需求表的整体缩放系数（经 `Options.DemandScale`/`sim` 进入消费目标与需求锚），
  k 偏低 9.3% 意味着价格方程的名义需求系统性低于契约标定意图。

### S3. 需求弹性：包默认与三个导出函数仍是被废止的常弹性口径
