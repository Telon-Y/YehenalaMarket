## 二、严重偏差（按严重度排序）

### A【致命·会让部门永久出清】§5.2 解雇侧只有 0 下限，且利润率信号与雇佣率无关

- 代码（**唯一的界**是恰好 0，没有正下限）：
  ```go
  // gosim/internal/build/build.go:301-305
  func AdjustHire(hireRate, marginEMA, expectedMarginRatio float64, p model.Params) float64 {
      step := p.HireAnnual / float64(p.TicksPerYear)
      if marginEMA < 0 {
          return math.Max(0, hireRate-step)      // ← 下限恰为 0
  ```
  增雇侧为 `return math.Min(1, hireRate+step)`（`build.go:314`）；每 tick 只调用一次（`sim/step.go:1425`）。
- **契约本身没有下限**（§5.2:1439-1440、§5:1333-1356 均只写幅度）⇒ 这不是"实现偏离契约"，而是**契约级缺陷**；代码把数学上的负值钳到 0，是唯一可辩护的实现选择。
- **ACTIVE 的说法需要加条件**：`docs/ACTIVE.md:239`（§四第 8 项）与 `:261-262` 称"对负利润率**单调向下且无下限** ⇒ 减到 **0** 后再也回不来（末态失业 86 万，故不是缺人）"。核实结果：
  1. "无下限"不准确——下限**存在且恰为 0**（`build.go:304`）；准确说法是"**没有正下限**"。
  2. 单调降到 0 成立：从 1 到 0 需要约 $1/0.0009615 \approx 1040$ 个连续负 margin 的 tick（与 R43 实测"tick 1,179"同量级）。
  3. **0 不是吸收态**：利润率是**名义满编口径**，与雇佣率无关——`sim/step.go:507-511`（`fullCapacityCosts`，`revFull = Level × Qty × P`）⇒ 一旦价格信号转正，`expectedMarginRatio` 在 hire=0 时返回 1（`step.go:1882-1884`）⇒ 下一 tick 即 `0+step` 复工。
  4. 因此"永久钉死"的真实条件是**价格信号长期 ≤ 0**（R43 的农业正是被 1:1 自给农场的供给压到零利润价之下），而非解雇规则本身。**结论：A 的真身是"缺少正下限 + 缺少自给供给隔离"，两者任一单独都存在时不必然致死。**
- 影响面：R43 的谷物农场/棉花种植园（雇佣率 → 0）；与 §4.1 的 `min()` 缺陷叠加时，任何一次价格跌破成本都会把该部门钉住很久。

### B【致命·冻结扩建】§4.1 `min()` 使"每超 5 点多扩 1 个"失效 ⇒ 意向恒为级数×10%
