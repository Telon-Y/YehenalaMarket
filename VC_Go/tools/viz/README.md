# 1.0 数据可视化面板 —— 中文说明

> 这一份是 **`VC_Go/tools/viz/` + `out/viz/`** 的 README。
> 本项目其他 README 的分工见文末「相关文档」。

---

## 一、这是什么

一个**自包含的 HTML 面板**，把 1.0 契约的静态结构与 gosim 的实跑数据放在**同一屏**里对照。
用途是「粗略地看一眼数据」：不需要读 Go 代码，也不需要跑模拟，打开浏览器就行。

**没有外部依赖**：没有 CDN、没有 npm 包、没有网络请求，图表是手写的内联 SVG。
把它拷到任何一台机器上、断网也能打开。

## 二、怎么看

### 最快的两种方式

| 方式 | 操作 |
|------|------|
| **交互式** | 双击 `out/viz/dashboard.html`（或拖进浏览器）。参数探查与悬浮提示只在浏览器里可用 |
| **只看一眼** | 打开 `out/viz/dashboard-full.png`（整页截图，1500×3400） |

浏览器里所有图表都支持**鼠标悬停看具体数值**（每个数据点/柱子/色块都带 `<title>`）。

### 页面结构

```
┌─ 顶部结论条：验收未通过 · 游戏内核不能 · 谱半径 · L* 对照 · 记账不变量
├─ KPI 卡片 ×9
├─ 总建筑级数（实跑）        │ 人口（实跑）
├─ 政府现金池 vs 债务上限（通栏）
├─ 价格比 P/P_cost（实跑末态）│ 财政量级（契约 L* 复算）
├─ 部门利润率热力带           │ 验收判据对照表（契约 §8.4）
├─ 平衡等级 L*：契约声明 vs 配方反解（通栏）
└─ 参数探查：政府持股 s × 交易税率 t（通栏，可拖动）
```

## 三、逐图说明：每一张图在说什么

### 1. KPI 卡片

| 卡片 | 含义 | 期望值 |
|------|------|--------|
| 标定谱半径 | 投入系数矩阵 A 的谱半径，契约 §3.4 的可行性硬校验 | 0.500000（< 1 才存在正的零利润价） |
| 实跑谱半径 | 同一量的实跑打印值 | 与本地复算一致 |
| P_cost 复算偏差 | 由 §3.3 配方 + §5 工资解零利润价，与 §3.1 价格表逐一比对的最大相对偏差 | 0.0644%（全部来自价格表取整） |
| L\*（契约定案） | §8.6 表列的平衡等级合计 | 688.61 级 |
| L\*（配方反解） | 由 §3.3 配方**独立反解**的平衡等级合计 | **733.05 级** ← 与契约不一致 |
| 政府缺口 | 政府工资义务 − 税收，以工资总额 W 为单位 | 0.563 W |
| 实跑末态总级数 | 3,000 周期末的总建筑级数 | 0（起点 84） |
| 实跑末态人口 | 3,000 周期末的人口 | 3,047（起点 1,000 万） |
| 判据汇总 | 实跑打印的「通过 N/M」 | 4/6（**契约 §8.4 实列 8 条**） |

### 2. 总建筑级数 / 人口

两条曲线：蓝实线 = 默认布点（契约 §3.2 的每种生产建筑 5 级），紫虚线 = 物质平衡布点。
两者的起点差 17 倍（84 级 vs 1,436 级），**但都归零**，只是死亡时点不同
（默认布点 tick 894 首次归零，物质平衡布点 tick 1334）。这张图是「换起点布点救不了经济」的直观证据。

### 3. 政府现金池 vs 债务上限

- 红：政府现金池。t=2 就转负，之后单调恶化，末态约 −4.96 亿。
- 粉：政府债务（= 现金池的负值部分）。
- 黄虚线：§4.5.4 的债务上限 = 2 ×（建造力产出 × 建造力价格）。**t≈520 归零** ⇒ G2（政府采购建造力）停摆。

### 4. 价格比 P/P_cost

背景三带：下沿红带 = `P_floor = 0.2×`，上沿红带 = `P_ceil = 5.0×`，中间绿带 = 合法带；
灰虚线 = `P = P_cost`。末态 11 种商品里 **9 种顶在 5.0×、1 种贴在 0.2×**，只有谷物停在 1.407×。
含义：价格几乎不再携带信息，§8.4 的 A1 判据（要求贴边占比 < 5%）在这种状态下恒判失败。

### 5. 部门利润率热力带

行 = 11 个部门，列 = 实跑抽样的 6 个 tick，格子里的数字是利润率（%）。
绿 = 盈利、红 = 亏损，颜色深浅按 |利润率| 渐变。
t=1 就有 8/11 个部门是负的 → §4.1 的「利润率 > 10% 才扩建」永不触发 → 只能靠 §4.4 单向缩编。

### 6. 验收判据对照表

契约 §8.4 实列 **8 条**（A1–A8），`report.Assess` 只实现 **6 条**。
表里逐条给出：判据原文、阈值、实测状态、实跑打印的细节、备注。
**A7（政府债务）与 A8（货币守恒）标为「未实现判定」**——而 A8 正是契约自己指定的
「唯一能识别系统死亡」的结构性判据。

### 7. 平衡等级 L\*：契约声明 vs 配方反解

蓝柱 = §8.6 表列值，红柱 = 由 §3.3 配方独立反解的值。读数：

- 下游六项（谷物/加工食品/织物/服装/高档服装/住房）**吻合到取整**（≤0.017%）；
- 上游四项（煤/铁/钢/工具）**红柱明显更高**：18.12 / 23.67 / 15.34 / 19.08 vs 契约的 7.56 / 7.56 / 7.56 / 9.08，即须 **2.0~3.1 倍**。

这一条直接解释了实跑里「铁配给比 0.375、钢产出归零」——**§8.6 的平衡点本身就没给上游留够产能**。

### 8. 参数探查（可交互）

拖动两个滑块：政府持股 `s` ∈ [0, 1]、交易税率 `t` ∈ [0, 70%]。
下面的网格里，行 = s、列 = t，**格子颜色 = 政府收支覆盖比**：

```
绿（≥100%）  政府收支自洽
黄（80~100%）接近
浅红（50~80%）
深红（<50%） 深度不可行
```

右上角同时显示「当前组合覆盖比」与「债务上限可支撑几个周期」。
契约默认点 **(s=0.70, t=0.10)** 的覆盖比只有 **19.6%**，债务上限只能撑 **0.31 个周期**。
要让政府自洽：`t` 需升到约 **46.5%**，或把 `s` 压到 **0.1506** 以下。

> 覆盖比的算法：`税收 / 政府工资义务`，其中税收 = `t/(1+t) × 税基`，
> 政府工资义务 = `s × 工资总额`，税基 = 最终需求价值 + 中间投入价值 + 建造力交易额。
> 全部由 `contract_data.json` 推导，与 `VC_Go/tools/survival_condition_probe.js` 同一套口径。

## 四、数据从哪来（两层，互不混用）

这是本面板的设计要点：**契约声明值**和**实跑实测值**分开存放，页面上也分开呈现，
避免「拿契约里的数字当成实测结果」。

```
VC_Go/tools/contract_data.json          ← 契约声明值（唯一数据源）
        │
        ├─→ VC_Go/tools/viz/gen_dashboard.js ──┐
        │      · 解零利润价（校验 §3.1）  │
        │      · 谱半径（校验 §3.4）      │
        │      · 反解 L*（校验 §8.6）     ├─→ out/viz/dashboard.html
        │      · 财政量级与参数扫描       │
        │                                │
gosim ──→ run-*.txt ──→ VC_Go/tools/viz/parse_run.js ──→ run-*.json ──┘
        （实测）         （解析器）                    （实测，结构化）
```

### `VC_Go/tools/contract_data.json`（契约声明值）

逐项转录自 `VC_Go/docs/1.0 生产与市场模拟.md`，每个字段都标了来源章节：

| 字段 | 契约出处 |
|------|---------|
| `goods` | §3.1 商品分类、需求弹性与价格（P_cost / P_init） |
| `buildings[].inputs` | §3.3 建筑投入产出表（每周期） |
| `finalDemand` | §8.6 表末列「最终需求」（人口 10,000,000，k = 1.04） |
| `equilibriumLevelsContract` | §8.6 表列 L\*（**只作对照，不作为推导输入**） |
| `params.wagePerLevel` 等 | §5 劳动力与工资 |
| `params.initialGovShare` / `taxRate` / `debtCapMultiplier` | §4.5.1 / §4.5.3 / §4.5.4 |
| `acceptanceCriteria` | §8.4 验收判据 A1–A8 |

文件里的 `_knownGaps` 记了**契约自己没规定的三处**（自给农场规模、建造部门与金融区的初始等级、
债务上限倍数的正文值与实现值不一致），面板不含这三项的「契约值」。

### `out/viz/run-*.json`（实测）

`market-sim` 只输出人类可读文本，所以中间加了一个解析器：

```powershell
# 1) 跑模拟，输出纯文本（注意：必须用 cmd 重定向，见第五节）
go run ./cmd/market-sim -ticks 3000 > out/viz/run-default-3000.txt

# 2) 解析成 JSON
node VC_Go/tools/viz/parse_run.js out/viz/run-default-3000.txt run-default-3000
```

解析器抓取五段：标定结果、开局状态、时序摘要、资金流分解、部门利润率、终态、§8.4 判据。
它处理了控制台宽度不足导致的**折行**（Go 的制表输出会把最后一列折到下一行）。

## 六、注意事项与已知限制

### 货币数字只作量级参考

同一参数重复执行时，**模拟不是逐位可复现的**：货币量级有约 0.01%~0.04% 的进程间抖动
（实测三次 `-ticks 52` 的政府现金池分别为 −61,048,286 / −61,048,123 / −61,063,887），
而离散量（总级数、人口、配给比）完全一致。

所以：**图上所有货币数字都只当量级看**，不要拿单次实跑的精确值当验收证据。

### 时序只有 6 个采样点

`market-sim` 的「时序摘要」是抽样表（tick 1 / 52 / 260 / 520 / 1000 / 3000），
不是逐 tick 序列。所以折线图是**采样折线**，不是完整轨迹——崩塌发生在哪两个采样点之间，
图上只能靠端点推断（准确时点可用 `-ticks 894` 这类方式二分，或给 `market-sim` 加 CSV 导出）。

### 不含「契约值」的三项

自给农场规模、建造部门初始等级、金融区初始等级——契约未规定，面板不显示它们的「契约值」，
只显示实现取值。

### 改这个生成器时的一条硬纪律

`VC_Go/tools/viz/gen_dashboard.js` 是 **UTF-8 且含中文**。
**不要用 PowerShell 的 `Set-Content` / `-replace` 改写它**——GBK 往返会把中文写坏，文件直接语法报错。
本项目已踩过两次（`VC_Go/docs/ACTIVE.md` 纪律第 2 条），请一律用编辑工具。

### 一处容易被搞反的数学

生成器里的 A 用的是**需求侧**约定：`A[i][j] = 生产 1 单位 j 所需的 i 数量`。
因此零利润价求逆的矩阵是 `δ_ij − A[i][j]`。

实测搞反（写成 `δ_ij − A[j][i]`）会让 11 个价格系统性错配，**最大偏差 822%**；
写对是 **0.0644%**。生成器里这段注释写明了推导，改动前请先读它。
