本地市场存在一个仓库带来的本地库存，本地库存为一固定值，当低于该值时仓库会自动向对应生产部门进行购买。而本地的生产建筑所需的全部原材料也将通过仓库下单，由A地的仓库向B地的仓库发出购买，再由B地的仓库向B地的生产建筑发出订单。
每个地区仓库针对每种商品维护：
现货库存：仓库实际持有的商品。
已预留库存：已被订单占用、尚未出库的商品。
在途库存：已经向上游购买但尚未到货的商品。
欠交订单：已经接受但暂时无法满足的需求。
目标库存：希望长期维持的数量。
补货点：低于此值才触发补货。
补货判断不能只看现货，否则运输期间仓库会每个周期重复下单。应使用库存头寸：
库存头寸 = 现货库存 + 已确认在途库存 - 已承诺出库数量
补货量 = max(0, 目标库存 - 库存头寸)
	本地生产建筑所需原料也应采用同样的逻辑。生产建筑只向所在地仓库提交“原料需求单”，不负责决定从哪个地区购买。所在地仓库先用本地库存满足，不足部分再选择其他地区仓库。
第一是重复计算需求。A 工厂对铜的需求是原始需求；A 仓库向 B 仓库采购、B 仓库向铜厂下单，都只是这项需求的派生订单。经济统计中不能把三张订单都算成新增最终需求。
第二是订单递归。如果 B 铜厂生产又需要煤，B 铜厂会向 B 仓库申请煤，B 仓库可能继续向 C 地采购。不要在一次函数调用里同步递归到底，最好按周期分阶段处理。
第三是库存振荡。固定目标库存、跨区运输延迟和逐级补货很容易产生“牛鞭效应”。

2.0新增国家实体，原先建造功能归属玩家所有，现在归属国家所有；即建造功能以国家为单位。每个国家拥有自己的国库，即原先玩家现金池。
生产建筑的雇佣率取决于其工资是否有竞争力。当其雇佣率低于期望雇佣率时，其会尝试提升工资（启用奖金模块）。

运输与仓库系统中，本地仓库会向本地市场根据52周期平均需求每周期发送一次对应数量订单。即本地仓库作为全部生产建筑的直接购买者，而其他所有购买需求都与本地仓库发生互动。
本地仓库间的贸易通过铁路枢纽进行。为了减轻计算量，忽视距离对于时间的影响，将距离的影响体现在铁路枢纽生产的商品“运力”上。运力价格=劳动力价格+生产原料价格。铁路枢纽作为“开发”类建筑，共享开发类建筑共性：1k劳动力每单位建筑等级、所有权归出资方所有、最大化雇佣率、政府雇佣劳动力由政府承担工资。距离对运输的影响体现在100单位物资需要购买运力数量上。

当建筑雇佣率大于90%，利润率为正且建造后期望利润率仍为正时，该生产建筑会加入潜在扩建队列；潜在扩建队列将根据实际单位建筑利润从高到低排序，而投资池会按照该顺序发起扩建请求进入扩建队列。投资池请求建造进入扩建队列需要扣除一笔启动资金：农业建筑100k，轻工业建筑200k，重工业建筑400k，矿物建筑400k。
